# 共享设计核心与媒介适配层的边界

> 依据：`docs/lighthouse-plan.md` §4「一个设计核心，多种媒介适配器」。
> 一句话规则：**共享的是设计决策依据，适配的是媒介表达与工程实现。** 两者混在一起，第二个媒介出现时必然靠复制。

## 1. 为什么现在就要定这条边界

现在仓库里 15 份 `references/` 是混着放的：`design-principles.md` 讲的对齐、邻近、对比在任何媒介都成立；`layout-recipes.md` 的 L01–L15 与 `thresholds.json` 里的 12 栏网格、0.6 in 安全边距，只在**绝对坐标的幻灯片画布**上成立。

如果不先标注边界，加 Word 分支时只有两条路：把幻灯片规则硬套到流式排版上（必然失败），或者另起一套互不相干的知识（等于把项目拆成两个）。灯塔规划把这条路封死了：

> "页面元素使用绝对坐标"是特定画布模型的实现方式，不是所有设计媒介的共同规则。

## 2. 三类资产

| 类别 | 定义 | 未来位置 | 现状 |
|---|---|---|---|
| **A 共享设计核心** | 换一种媒介仍然成立的决策依据（层级、间距、对比、色彩角色、文字层级、图文关系、叙事、可访问性） | `core/`（尚未迁移） | 混在 `references/` 中 |
| **B 幻灯片适配层** | 只对 16:9 绝对坐标画布成立的规则（栏网格、坐标、页间节奏、版式签名、密度上限） | `media/slides/`（尚未迁移） | 混在 `references/` 与 `schema/` 中 |
| **C 新媒介适配层** | Word / 固定版面 / 网页各自的规则集 | `media/documents|fixed-layout|web/` | 未建 |

**本轮只做标注，不搬文件。** 搬文件会打断现有链接、脚本与 42 项检查的路径，成本高于收益；等第二种媒介真正开工（阶段 1）再按本节迁移，并把迁移写成 ADR。

## 4. 三条硬规则

**触发条件**：往 `references/` 新增或修改规则；或开始为第二种媒介写知识时。

**具体动作**：
1. 新规则先回答"换成 A4 流式排版还成立吗"。成立 → 标 A；不成立 → 标 B 并写明适用媒介；两者都有 → 拆成两段，各自标注。
2. 任何规则里出现绝对坐标、画布英寸、栏宽、页数、页间顺序，一律视为 B，不得写进 A 类文件。
3. 新媒介开工时**新建**该媒介的规则文件与版式编号，不复用 L01–L15、不复用幻灯片的字号阶梯；复用只发生在 A 类。

**常见错误**：
- 把"留白 ≥25%"当成通用原则——它是按 16:9 投屏距离算出来的，A4 正文页的留白逻辑不同（受装订、页眉页脚影响）。
- 把 L01–L15 直接当 Word 的版式目录——流式排版没有"页面版式"这个概念，只有章节结构。
- 为了让第二个媒介"看起来有知识库"，把 A 类文件复制一份改标题（等于两套互相矛盾的规则）。

## 5. 与路线图的关系

| 阶段 | 与本文件的关系 |
|---|---|
| 阶段 0（方向证据） | 不动结构；只在本表登记分类 |
| 阶段 1（文档） | 开工第一步：按本表把 A/B 拆开，迁到 `core/` 与 `media/slides/`，并更新脚本里的路径与 42 项检查的引用；此迁移必须写 ADR |
| 阶段 2（固定版面） | 复用 A + 新建固定版面规则；不得复用幻灯片版式编号 |
| 阶段 3（网页） | 复用 A + 新建网页规则（断点、交互、语义） |

## 6. 迁移时不能忘的三件事

1. `safe_margin_ratio`、12 栏网格、字号阶梯搬走后，`scripts/` 里读 `thresholds.json` 的代码要同步改路径，否则 42 项检查会静默失效（这是最危险的失败模式：检查还在跑，但读的是空值）。
2. 迁移必须一次性完成并跑全套回归（`docs/v2-plan-ops.md` §7 的 `regress_ppt.py` 三个 diff 全 0），不能中途留一半。
3. 迁移后的目录树要同步进 README 结构树与 `docs/v2-plan.md` §4，避免出现"文档说在 core/，实际还在 references/"的漂移。
