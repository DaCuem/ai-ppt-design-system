## 一、项目定位

把"帮我做个 PPT"变成一条可检查的生产线：`deck.json` 进，可编辑 PPTX 出；版面先算、再排、再渲、再机检，最后由人看图拍板。

不做某一份特定 PPT，做的是**可复用、跨主题的设计能力**：需求探索 → 内容审计 → 文案 → 方向选择 → 视觉系统 → 页面架构 → 逐页制作 → 质量复核 → 迭代交付。

## 三、已建成什么

### 3.1 主流程（8 阶段 + 1 个插入阶段）

```
0 需求探索 → 1 内容审计 → 1.5 文案生产 → 2 方向选择 → 3 视觉系统
        → 4 页面架构 → 5 逐页制作 → 6 质量复核 → 7 迭代交付
```

每阶段有产出物与门禁，前一阶段没过判据不进下一步；阶段 2 强制 ≥3 个实质不同方向 + 六维评分；阶段 6 分 P0–P3 四级，P0 阻断交付。

### 3.2 六条命令的闭环

| 命令 | 作用 |
|---|---|
| `probe.py` | 探本机能力（Python / 字体 / 渲染后端），缺什么报什么 |
| `build_pptx.py` | `deck.json` → 可编辑 PPTX（`--check-only` 只校验不构建） |
| `copy_check.py` | 文案机检（槽位字数、空话、AI 句式、无出处数字） |
| `qa_check.py` | 版面机检 30 项（溢出、越界、对比度、重复、密度、像素密度） |
| `render.py` | PPTX → PNG（144 dpi / 1920×1081，本机 LibreOffice 后端） |
| `contact_sheet.py` | 多页总览图，一次看完整份节奏 |

### 3.3 设计知识库

| 内容 | 数量 |
|---|---|
| 视觉风格（每种 14 项，含"容易被误读的表面符号"与"转化为版面的操作步骤"） | 10 种 |
| 页面版式（适用 / 不适用 / 结构 / 阅读顺序 / 2 种变化 / 常见错误 / ASCII 线框） | L01–L15 |
| 反模式（症状 / 模型先验 / 判据 / 修正动作 / 替代做法） | AP-01–AP-16 |
| 专项参考 | 字体、色彩、图像、图表、节奏、可访问性 6 份 |
| 外部阅读清单（29 条，逐条标核验方式：本机 200 / 搜索桥抓正文） | 1 份 |

### 3.4 42 项机器检查

| 分组 | 检查项 | 管什么 |
|---|---|---|
| 版面 | OVF / GEO / OVL | 文字溢出、越画布、元素重叠 |
| 结构 | STR / CNT / REP | 页号连续、必填字段、版式签名重复 |
| 字体与色 | TYP / COL / CON | 字号层级、色相数量、对比度 4.5:1 |
| 密度 | DEN | 每页元素 ≤14、文本块 ≤4、字数 ≤220 |
| 图像 | IMG-01 | 有效像素密度（<110 ppi 提示，<80 ppi 阻断） |
| 文案 | CP-01…CP-12 | 槽位字数、空话、AI 句式、无出处数字、审校残留 |

机检只报**事实与位置**（第几页、哪个元素、超了多少），不报"好不好看"。

### 3.5 文案环节（阶段 1.5）

- 用户没给文案 → 先出逐页文案稿 → 交用户审核 → 定稿冻结 → 才进排版
- 三档解决"AI 味"：宿主已装 skill → 联网装开源工具（须先获许可）→ 换模型改写
- 换模型时**只传用户要求**（受众、场合、语气、人称、用词禁忌、必须保留项）+ 输出格式 + 版面字数上限；本 skill 的句式规则、禁用词表、机检项一律不传
- **判定权与验收权在用户**：机检只报位置；`[已确认]` 必须来自用户原话或选择编号；用户不答复记 `[假设]` 并在交付说明点名

## 五、关键设计决策（及理由）

| 决策 | 理由 |
|---|---|
| **spec-first**：`deck.json` 为唯一源，PPTX 是产物 | 版面可计算→可检查→可复现；改一处不用重排整份 |
| `thresholds.json` 作为阈值唯一真值 | 文档只引用、脚本直接读，避免数值在多处漂移 |
| 框高用 `行数 × 字号 × 行距 × 1.204` | 1.204 是 144 dpi 实测行盒比（四族字体误差 ≤0.3%），溢出能在构建前算出来 |
| 不提供 themes 预设皮肤 | 避免所有 deck 长得一样；只给 tokens 示例，让每个项目自己定 |
| 机检 0 条 ≠ 好看 | 机器管可计算的，人眼管构图、文字与叙事，两轮都要过 |
| 判定与验收归用户 | 像不像 AI 是读者感受、改好了没有是作者判断，模型自评等于没评 |
| 换模型只传用户要求 | 传我的规则过去，产出只是同一套偏好换台机器跑 |

## 七、已知限制

1. 只验证了 16:9 与三族字体（Microsoft YaHei / Noto Sans SC / Source Han Serif）；A4 竖版实测可用，但字号阈值仍按投屏距离标定，需要新一套 print 阈值
2. 渲染走本机 LibreOffice 后端；其他后端未逐一验证
3. PDF / Word / 固定版面（A4 海报）/ 既有 PDF 改版：**已出规划与操作书，P0 尚未开工**
4. 不改既有 PDF 的文字（只能底图重排 / 遮挡 / 覆盖）；.psd 无可用库，改用 SVG + 分层 PNG
5. 不做审美评分：机检 0 条不等于好看，人眼复核是必做环节
6. 阶段 0 的需求探索未在真实用户身上做对照实验
7. 长 deck（>30 页）与图片极密集的版式未做专项验证
