## ADR-002：`recolor` 采用 sRGB 欧氏距离 + 区域口径，替换率降为辅助指标

- **日期**：2026-11-15（追溯记录；决策形成于 v2 R2 修订）
- **状态**：已接受
- **提出人**：外部审阅意见（GPT）+ 执行 AI 落盘
- **背景**：PDF 改版的 `recolor` 原先写"替换率 ≥95% 即通过"，但没有口径：统计哪个区域、颜色距离怎么算、容差怎么影响、抗锯齿边缘算不算、分母是什么。口径未定，这个数字就不是验收标准，而是可以被任意解释的宣传数字。
- **目标**：服务 P5（机器检查只判可计算项）、P7（可复现）。
- **方案**：
  1. 统计范围必须显式给出 `region`（矩形）与 `exclude`（排除区，例如 logo）。
  2. 颜色距离用 sRGB 欧氏距离，`tolerance` 默认 30（范围 0–60），超出不替换。
  3. 边缘 1.0–1.35 倍距离区段只做 50% 混合以避免光晕，且**不计入分母**。
  4. 分母 = 目标色像素数（hits），替换率仅作辅助提示（<90% 时提示"可能未改全"），不作为验收判据。
  5. 验收改用：before/after 对照 + 逐项变更记录 + 人工确认无明显色边。
- **备选方案**：只用"替换率高"作为单一判据。未选，因为它无法区分"改得准"和"糊成一片"。
- **影响**：`docs/v2-plan.md` §1.2.2、§6/§8；`docs/v2-plan-ops.md` §5.3 的伪代码（删除未定义的 `from_mix`）。
- **风险**：容差 30 在渐变背景上可能仍留有可见色边，需人工复核；已在验收中把"人工确认"列为必须项。
- **验收**：伪代码可执行、口径四要素都在文档里、替换率出现在"辅助提示"而非"验收标准"位置。
- **回滚**：若实测发现容差设置不可用，可调 `tolerance` 与边缘混合比例，但**不得**删除 region/分母定义。
- **证据**：`docs/v2-plan.md` §1.2.2；`docs/v2-plan-ops.md` §5.3。
