## ADR-001：引入长期方向校准书，并新增「阶段 0：方向证据」

- **日期**：2026-11-15
- **状态**：已接受
- **提出人**：项目发起人（发起）+ 执行 AI（落盘）
- **背景**：v2 规划书（R2）从"文档骨架"直接开工，但项目最大的未知数从未被检验——「设计知识库是否真的改变了 AI 的设计结果」。仓库里有规则、有案例、有机检，但没有对照实验；继续加媒介只会让"没证明的核心"承载更多功能。同时，现有规划把 PPT 当作项目边界（定位写的是"AI PPT 设计系统"），而长期目标是"一个设计核心 + 多种媒介适配器"。
- **目标**：服务 P1（设计知识必须参与决策）、P2（知识要可执行）、P5（机器检查与人的判断分工）、P7（可复现可交接）。具体是把"证明知识库有效"变成开工前的硬门槛，而不是宣传口号。
- **方案**：
  1. 把发起人提供的《长期发展规划与方向校准书》原文收进 `docs/lighthouse-plan.md`，作为**方向基准（契约级）**，与执行方案分层：它说"有没有走偏"，`v2-plan` / `v2-plan-ops` 说"怎么做"。
  2. 新增 **阶段 0：方向证据**（基准任务 + 消融实验 + 盲评 + 结论分级），操作手册独立成册 `docs/stage0-direction-evidence.md`。
  3. 原 P0–P4（文档骨架 → 文档完整 → 设计型导出 → PDF 改版 → 验收）重命名为**阶段 1–3**，降为阶段 0 之后的执行内容；网页/统一入口记为阶段 3/4，不进 v2 承诺。
  4. 新增配套：`docs/evaluation/`（协议与结果区）、`docs/capability-status.md`（四级能力状态）、`docs/design-core-boundary.md`（共享核心 vs 媒介适配层）、`templates/media-proposal.md`、`templates/adr.md`、本记录区。
  5. 版本序列改为 `1.5.0（阶段 0）→ 1.6.0（文档骨架）→ 1.7.0（文档完整）→ 1.8.0（固定版面/PDF）→ 1.9.0（验收发布）`。
- **备选方案**：
  - 备选 A：先做完文档分支，再补实验。未选，因为文档分支会把"绝对坐标画布"的知识再复制一份，若之后发现知识库无效，复制出的结构更难回收。
  - 备选 B：只把灯塔规划当阅读材料放进 `docs/`，不改现有路线。未选，因为第 3 章明确要求"注意文档/PPT 计划是否只服务单一媒介"，不改就等于承认跑偏。
  - 备选 C：直接按灯塔规划重写全部规划书。未选，因为现有 R2 的工程细节（三层 QA、preset、recolor 口径）已经过外部审阅修订，推倒重写等于丢弃已验证部分。
- **影响**：`docs/v2-plan.md` 第 9 章阶段表与第 12 章版本序列、`docs/v2-plan-ops.md` 第 0.3 节映射表、README 与 `SKILL.md` 的定位表述、`docs/project-summary.md` 的进度与时间线、`CHANGELOG.md`、发布包内容。检查脚本与阈值不变。
- **风险**：① 阶段 0 的消融实验需要干净会话与盲评，单人环境下容易"自己评自己"（已在协议中要求披露评审者身份）；② 新增 5 份文档会让"文件数增长"看起来像进展（已在 `capability-status.md` 明确区分"文档"与"能力"）；③ 阶段 0 未完成期间，PPT 分支的既有结论仍只能标"已实现"，不能升为"已验证"。
- **验收**：① `docs/lighthouse-plan.md` 在仓库内且被 README 索引；② `docs/stage0-direction-evidence.md` 的 S1–S9 可执行、有命令；③ `docs/v2-plan.md` 第 9 章阶段表包含阶段 0 且与操作书映射表一致；④ `python scripts/selfcheck.py --strict` 与 `python scripts/stats.py --check` 全绿；⑤ 项目总结与 CHANGELOG 的时间线出现 1.5.0 且写明"只加规划与文档，未写新代码"。
- **回滚**：若阶段 0 被判定不可执行（例如无法做到干净会话），保留 `docs/lighthouse-plan.md` 与协议文件，把阶段 0 降级为"长期待办"，阶段 1 恢复为最早开工项；旧版本 tag 与发布包不受影响（本轮不改代码，回滚只涉及文档）。
- **证据**：`docs/lighthouse-plan.md`、`docs/evaluation/ablation-protocol.md`、`docs/capability-status.md`、`docs/design-core-boundary.md`、`docs/v2-revision-notes.md` 的 R3 章节。
