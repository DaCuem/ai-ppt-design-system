# 实验结果存放区

> 协议见 `../ablation-protocol.md`，基准任务见 `../baseline-tasks.md`。

## 当前状态

**未开始。** 这里还没有任何结果，因此仓库中不得出现"知识库已被证明提升设计质量"这类表述（见 `../../capability-status.md` 的四级定义）。

## 目录命名

```
results/<日期>-<任务号>-R<仓库版本>/
```

例：`results/2026-11-20-T1-R1.5.0/`

## 每轮必须有的东西

| 文件/目录 | 内容 |
|---|---|
| `run.json` | 任务号、仓库版本与 commit、模型与参数、运行时长、人工修改量、产物清单 |
| `A/` | 对照组（不提供知识库）的 deck.json、pptx、preview/、qa.json、copy.json |
| `B/` | 实验组（按工作流调用知识库）的同上产物，外加 `knowledge_refs.json` |
| `anon/` | 匿名对照图 `P01.png`/`P02.png` 与 `mapping.json`（谁是谁） |
| `scores/` | 评审表，每人一份，格内必须写证据 |
| `report.md` | 按协议第 7 节的十项写 |

## 历史结果不可覆盖

- 同一任务同一版本只跑一次并落盘；要重跑就新建带 `-rerun` 后缀的目录。
- 发现旧结果有错：不删，另写 `erratum.md` 说明错在哪、影响哪些结论。
- 删除记录等同于修改结论，需走 `../../docs/governance.md` 的提案流程。

## 检查清单

- [ ] 目录名符合 `<日期>-<任务号>-R<版本>` 格式。
- [ ] `run.json` 的 12 个字段齐全，模型版本与 commit 可核对。
- [ ] A/B 两组产物齐全，能各自独立重建。
- [ ] `anon/mapping.json` 与评分表分离保存，评审时不可见。
- [ ] `report.md` 含失败案例与"尚不能证明的内容"。
- [ ] 没有覆盖或删除过历史结果。
