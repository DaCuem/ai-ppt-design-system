## 1. 逐条处理

### 1.1 §2.1 P0 不能有 toc

- **处理**：采纳。P0 schema 只列 `heading / paragraph / list / table / figure / pageBreak` 六块；`toc` 移到 P1；新增 `DOC-16`「块类型未在该阶段实现」（P0 级）来机械拦住越界。
- **落点**：规划书 §5.3 块表"首实现"列、§8 映射表 `DOC-16`；操作书 §2.4 禁用清单、§2.6 样张"无目录页"。

### 1.2 §2.2 P0 样张降为 3–4 页

- **处理**：采纳，取 4 页（3 页装不下"问题/方法/结论"三段 + 封面）。字数预算 700–900，并写死"不许为凑页数加空白或分页"。
- **落点**：规划书 §9.3 完成标准 A0 组；操作书 §2.6 逐页表、§2.10 失败表"末页空白"行。

### 1.3 §2.3 拆 `qa_doc.py` 三层输入

- **处理**：采纳。`qa_doc.py` 支持 `--doc` / `--docx` / `--pdf --preview-dir` 三组输入；每项检查声明自己需要的层；缺层记 `SKIP` 并计数；**`skipped > 0` 不许签收**。
- **落点**：规划书 §6.4（三层示例 + 16 项表含"层"列）、§8 映射表；操作书 §1.5、§2.8、§2.9。

### 1.4 §2.4 版本号其实是功能开发顺序

- **处理**：**采纳（澄清后）**。第一次读这条建议时我理解错了：我以为它在规定「发布编号」，于是用「单调递增」去化解，还把序列改成 `v2.0.0 → v2.2.0 → v2.3.0`。
  用户指出（m02069）：**「gpt对于版本号的修改建议其实是针对功能开发顺序的，不是单指版本号发布顺序，发布顺序正常迭代就好了」**。
- **改正**：发布号按正常迭代走 `1.4.1 → 1.5.0（P0）→ 1.6.0（P1）→ 1.7.0（P2）→ 1.8.0（P3）→ 1.9.0（P4 只加案例与文档）`；本文标题里的 `v2` 只作功能线名称，不写进版本号。功能顺序 P0 → P1 → P2 → P3 本身单调，因此「先做编号小的功能」天然满足。
- **教训**：审阅意见里的「版本」可能指功能编号，也可能指发布编号；两种含义要分开问清楚，不要用一个方案同时糊住两个问题。
- **落点**：规划书 §9.1 版本列、§12、附录 D2；操作书 §6 打包命令。

### 1.5 §2.5 PDF 改版能力边界与 recolor 口径

- **处理**：采纳。新增 §1.2.1「承诺 / 不承诺」两条清单；§1.2.2 给出可验收口径（`region`、sRGB 欧氏距离、`tolerance` 30±、边缘 1.0–1.35 倍只 50% 混合且不计入分母、分母 = `hits`）；替换率降级为**辅助提示**，不作为验收项；伪代码删除未定义的 `from_mix`，改用 `mix()`（与 `qa_check.py` 的 `blend_alpha` 同语义）。
- **落点**：规划书 §1.2.1、§1.2.2、§1.2 不做清单；操作书 §5.2、§5.3、§5.4。

### 1.6 §2.6 SVG / 分层 PNG 边界

- **处理**：采纳。SVG 支持 `rect/line/ellipse/polygon/text/image`；`chart/table/icon` **默认跳过并 rc=1**，加 `--allow-raster` 才位图化；`skip-report.md` 四列；`<desc>` 写明位图化元素数。`layers.json` 六字段（name/order/file/bounds/opacity/sourceElementIds/rasterized）+ 明写"文字层是位图，改字用 SVG 或源文件"。
- **落点**：规划书 §6.5、§6.6；操作书 §4.3、§4.4。

### 1.7 §2.7 可执行的 PPT 回归基线

- **处理**：采纳。冻结 v1.4.0 为基线：代码与 schema 比 SHA-256；**pptx 比 zip 成员 CRC**（不比文件 sha，因含时间戳）；QA `SUMMARY` 行逐行比对；contact sheet 像素差 ≤0.5%。每阶段收尾跑 `regress_ppt.py`，三个 diff 必须全 0。
- **落点**：规划书 §2.5；操作书 §7。

### 1.8 §3 / §3.1 两份文档一致性 + 页数四段判据

- **处理**：采纳。原本"目录末条页码 = PDF 页数"降级为**第 3 段抽查**的一部分，主判据改为四段：区间 / 目录覆盖 / 抽查页码一致 / 无空白页与重复页码。
- **落点**：规划书 §10 验收总表；操作书 §3.6。

### 1.9 §3.2 QA 映射表

- **处理**：采纳。规划书 §8 给出 23 项表（`DOC-01…16`、`PRT-01/02`、`PDF-01…03`、`EXP-01…03`），列含检查对象、所需输入、实现阶段、严重程度、对应 fixture；与已有 42 项合计 65 项。
- **落点**：规划书 §8；操作书 §2.9（fixture 对应）、§2.8（命令）。

### 1.10 §4.1 统一命令行环境

### 1.11 §4.2 文件大小 / 页数降级为辅助指标

- **落点**：规划书 §1.2 不做清单、§5.3 首实现列；操作书 §3.5。

### 1.15 §8 指令

- **处理**：逐条对照：以现有文件为基础修订（✔ R1 文件名与结构保留）；优先 P0 问题（✔ 本轮 9 条修订里 6 条落在 P0）；改一份同步另一份（✔ 见 §2 一致性检查）；不只改文字（✔ 表、命令、 fixture、验收项同步改）；不写"理论可行"为"已实现"（✔ SVG 在 Inkscape/AI 中可编辑标 V18-a 待验证）；完成后输出修订稿 + 摘要 + 未解决 + 一致性检查（✔ 本文件）；本轮不动代码（✔）。
