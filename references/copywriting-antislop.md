# 去 AI 味（Anti-Slop）

> 本文件管「写出来像不像人写的」。文案该写什么在 [`copywriting-patterns.md`](copywriting-patterns.md)；流程在 [`../workflows/01b_copy-production.md`](../workflows/01b_copy-production.md)。
> 适用范围：PPT 文案、文档正文、海报标题——**所有产出形态的文案都用这一份**。

## 1. 立场：判定权和验收权都在用户手里

**本 skill 不判定「像不像 AI」，也不宣布「改好了」。**

- 「像不像 AI」是读者的感受。只有作者、受众、或用户本人能拍。模型觉得"读着还行"没有任何证据价值——它的判断标准和它的生成偏好同源。
- 「改好了没有」是同一件事的另一面。`copy_check.py` 只能证明"没有可数的硬伤"（字数超标、空话命中、句式命中），证明不了"读起来是人话"。

所以本文件只做四件事，按顺序：

1. **摆事实**：把可数的东西列出来（§2），不附带结论。
2. **给选项**：把可用的外部路径摆出来（§3、§4），由用户选。
3. **执行**：按用户选定的路径跑，一步不多做。
4. **请用户判**：把改前/改后并排摊开，问三个问题（§5），等答复。

三种越权都算违规（见 `SKILL.md` 红线 17）：

- 不摆事实就自称"已去 AI 味"；
- 摆了事实就替用户下结论（"这段我判断已经不像 AI 了"）；
- 用户说"不行"就关起门自己再改一遍。

## 2. 可数事实清单（不是判定结果）

下面 12 组是**能被数出来的事实**。用途有两个：用户说"这段读着假"时帮他指到具体的行；工具改完之后确认没引入新的机械感。

| # | 可数事实 | 怎么数 | 怎么向用户描述（原话示例） |
|---|---|---|---|
| 1 | 空话短语 | 命中 `thresholds.copy.emptyPhrases` | 「第 2 页有『进一步深化』『形成闭环』，这两处要不要删掉？」 |
| 2 | 形容词顶替证据 | 命中 `copy.fillerAdjectives` 且同句无数字 | 「第 5 页『显著提升』没给数，改成具体数字还是删掉？」 |
| 3 | 同长句堆叠 | 连续 3 句字数相同（±1） | 「第 3 页三句都是 15–16 字，读着像排比，要打散吗？」 |
| 4 | 三段排比 | 「既…又…还…」「不仅…而且…」 | 「第 7 页这句是『不仅…而且…』句式，保留还是拆开？」 |
| 5 | 连接词开头 | 每段首词都是「此外/同时/因此」 | 「这三段开头都是连接词，删掉会不会更顺？」 |
| 6 | 冒号列表 | 一句里 `：A；B；C；D` ≥3 项 | 「这句用了四个分号项，改成三行短句？」 |
| 7 | 数字无出处 | 有数字但该页无 `source` | 「6.8 K 这页没有出处行，补一条还是删掉这个数？」 |
| 8 | 名词化 | 「进行了优化」「实现了提升」 | 「这两处是『进行了…』，改成动词直陈？」 |
| 9 | 全称判断 | 「所有/全部/一定/必然」 | 「『全部方案』其实是三套，改成『三套方案』？」 |
| 10 | 情绪副词 | 「极大地/显著地/有效地」 | 「这两个副词删掉，直接给对比数？」 |
| 11 | 无必要中英混排 | `我们的 solution` 类 | 「这里中英混排，统一成中文？」 |
| 12 | 句长过均匀 | 全篇句长标准差 < 4 字 | 「整页句子都差不多长，加一句 4 字短句？」 |

**必须说清的一句**：命中不等于"像 AI"，没命中也不等于"像人"。这份清单只负责"指位置"，不负责"下判决"。

## 3. 三条外部路径（按优先级，不许跳回"自己改"）

| 顺序 | 路径 | 前提 | 谁执行 | 做法 | 记录到 |
|---|---|---|---|---|---|
| P1 | **宿主已装的润色 skill** | 用户环境里已有（本机已装 `humanizer-zh`，见下） | 我 | 先读该 skill 的 `SKILL.md`，按它自己的流程跑；**小批**（≤6 页）试改，对照前后再放量 | `records/copy-antislop.md`：skill 名 + 版本 + 改了哪些句 |
| P2 | **联网找开源工具** | 用户**明确同意**联网检索与安装 | 我搜选，用户批准安装 | 按 §4 标准筛出 2–3 个候选 → 给理由与许可 → 用户点头 → 装/用 → 记录仓库、commit、许可、核验日期 | 同上 + `assets/licenses.md` 补一行 |
| P3 | **换一个模型审校** | 用户愿意把文本交给第二个模型（qwen / gpt 等） | 用户 | 我出交接包（§6），用户贴给另一个模型，拿回表格我合并 | `records/copy-crosscheck-merge.md` |

默认顺序 **P1 → P2 → P3**。P1 不可用且用户不同意 P2 时，直接 P3，**不得退回"我自己改一遍"**。

## 4. 联网选工具的标准（GitHub 优先）

**硬条件（缺一不选）**

1. 许可证明确且允许商用：MIT / Apache-2.0 / BSD 优先；`NOASSERTION`、无 License 一律不用。
2. 近 6 个月有提交（看 `pushed_at`，不看 stars 攒了多久）。
3. 目的正当：**明确排除"绕过查重 / 骗过 AI 检测器"类工具**——那是学术不端工具，不是写作工具。
4. 有可运行形态：skill、CLI、Python/JS 包，或可本地跑的 Docker；纯 prompt 截图、纯网页 SaaS 不算。
5. 能离线或明确说明会把文本发到哪里（涉及未公开内容时，必须离线可跑）。

**排序**：stars 降序 → 最近提交 → 中文适配 → 有 release（下载量可查）→ 文档完整。

## 5. 验收：把判断交回去，问三个问题

改完（或决定不改）之后，不写"已通过"，只做这三件事：

1. **并排摊开**：给用户看改前/改后（逐页对照，改动处标出来），或原稿 + 说明"这版没动"。
2. **问三问**：
   - 「整体读起来像 AI 写的吗？」——像 / 不像 / 说不清
   - 「具体哪几句？」——让用户指，我逐条记进 `records/copy-antislop.md` 的"用户指认"列（不改写成我的说法）
   - 「这版你接受吗？」——接受 / 不接受 / 再改一轮
3. **落签字**：接受 → `copy-deck.md` 状态列写 `[已确认]`，来源必须是**用户原话或选择编号**；不接受 → 回 §3 换路径或换工具，不许换回自己改；说不清 → 给两版让他选（A 原稿 / B 工具改后），不替他评。

用户不回：记 `[假设]`，交付说明里点名「文案未经用户验收」。**不许把没答复写成"已通过"。**

**触发条件**：任何一次去 AI 味动作之后；或用户说"看着还是假""说不清哪里怪"。
**具体动作**：并排摊开改动（标出改了哪几处）→ 按上面三问逐条问 → 按答复落 `[已确认]` 或 `[假设]` → 把三问的原话记进 `records/copy-antislop.md`。
**常见错误**：把"工具跑过了"当成"用户接受了"；替用户写结论（"现在读起来自然多了"）；用户说"说不清"就自己拍板通过。



## 6. 换模型改写：交接包格式（只传用户要求，成品直接交回）

第二个模型是**改写者**，不是评审者；也不是我的执行器。所以要它给成品，但**只给它用户的要求**——把我总结的句式偏好、禁用词表、机检项发过去，它只会产出"像我"的句子，那还是同一个模子的文案，只是换了台机器跑。

### 6.1 只传两件

| 传什么 | 具体内容 |
|---|---|
| ① 用户的要求 | 受众、场合与时长、语气、人称、用词偏好与禁忌、必须逐字保留的数字/单位/专有名词/引用出处 |
| ② 输出契约 | 逐页逐槽位**完整文案表格**；未改动的槽位也原样抄回；不写理由、不写建议、不标改动处；末行 `END 总页数 / 总槽位数` |

唯一附带的约束是**各槽位的字数上限**——这是版面物理容量，不是文风偏好：超过就放不进固定版面，而删哪句不该由我替用户决定。模板见 [`../templates/copy-crosscheck-prompt.md`](../templates/copy-crosscheck-prompt.md)。

### 6.2 故意不传的四样

| 不传 | 理由 |
|---|---|
| 本 skill 的句式规则（一页一句主张、结论前置、信息不重复） | 这是我的偏好，传过去它就照着模仿，产出同质化 |
| 空话清单 / AI 句式正则 / 填充形容词表 | 给了它就是教它绕开这些词——绕过检测，不是改文风 |
| 我标"哪几句像 AI"的结论 | 判断权在用户（§1）；我标了它只改那几句，其余问题原样留着 |
| 机检结果与抽样范例 | 前者等于让它填空，后者会让它复制我的文风 |

一句话：**本 skill 的规则在收回之后当验收尺，不当发送之前的笼子。**

### 6.3 批次与完整性

- 一次 ≤12 页（再多它会开始省略行）。
- **每批要求回全**：这 12 页的所有槽位都要出现，没改的逐字返回——合并时靠"行数对不对"发现它偷懒。
- 按「页 + 槽位」做键覆盖到 `records/copy-deck.md`；加了页、漏了槽位、把两页并成一页，整批退回重跑，不许我自己补。

### 6.4 我这边只做四件事

1. 合并（保留它给的原文，一个字都不润色）。
2. 算 diff：`页 | 槽位 | 原文 → 新文`，这是用户判断"接不接受"的唯一依据。
3. 跑机检，但**只作为事实清单**交给用户（哪页哪句超了多少字、命中哪条）；**不拿它回炉要求对方改**，也不当成"没通过"。
4. 超字数的项列给用户三选一：压字数 / 改版式 / 换一版。**不擅自删句**。

它的成品是候选，机检 0 条也不等于用户接受，最终仍由用户（§5 三问）拍。
