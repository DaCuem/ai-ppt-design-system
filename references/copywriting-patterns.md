# 文案规格（Copywriting Patterns）

> 本文件管「每一页该写什么、写多长、什么句式」。写法层面的去 AI 味在 [`copywriting-antislop.md`](copywriting-antislop.md)；逐页文案稿的载体是 [`../templates/copy-deck.md`](../templates/copy-deck.md)；流程在 [`../workflows/01b_copy-production.md`](../workflows/01b_copy-production.md)。
> 本文件里的字数上限与禁用词表**不在正文里定值**，全部读 [`../schema/thresholds.json`](../schema/thresholds.json) 的 `copy` 段；正文只解释怎么用。

## 1. 文案在流程里的位置

```
0 需求探索 → 1 内容审计 → [1.5 文案生产] → 2 方向选择 → 3 视觉系统 → 4 页面架构 → 5 逐页制作 → 6 QA → 7 交付
```

放在 1 与 2 之间的理由：文案决定每页的**信息量**，信息量决定版式能不能装下、决定节奏是密还是疏。先定视觉方向再写文案，等于先买柜子再量衣服。

**触发条件**：进入阶段 2 之前，`records/copy-deck.md` 不存在，或存在但有未确认行。
**具体动作**：回到阶段 1.5 补齐，不进入阶段 2。
**常见错误**：边做页边想文案。结果是每页字数随机，版面反复推倒，QA 的 `DEN-04`（字数超标）通常就是这里欠的债。

## 2. 一页一句话

**触发条件**：写任何一页的标题。
**具体动作**：标题写成**一句可判断真假的话**，不是话题名。判断方法：把标题读给同事听，他能不能回答"同意 / 不同意"。
**常见错误**：`音响结构设计`（话题名，无法判断真假）→ 改 `磁路在最前，盆架决定低频下潜`（可判断）。

| 话题名（不合格） | 判断句（合格） | 为什么 |
|---|---|---|
| 项目背景 | 立项时没有可对比的基线 | 有真假值 |
| 研究方法 | 42 个测点，6 周连续观测 | 数字可核对 |
| 数据结果 | 覆盖率每涨 17 点，风速降 44% | 量化关系 |
| 结论 | 先定遮荫结构，再算覆盖率 | 有动作顺序 |

## 3. 九个槽位与各自的字数上限

字数上限读 `thresholds.copy.limits`（按 16:9 版面容量推出来的，不是审美偏好；
换画布尺寸时按 `limitsScope` 的说明重算），下表只说明**槽位之间的分工**，避免同一句话在三个地方重复。

| 槽位（role） | 承担什么 | 不承担什么 | 上限键 |
|---|---|---|---|
| `coverTitle` | 这份材料的主张（一句话） | 不写公司名、不写日期 | `limits.coverTitle` |
| `lead` | 标题的展开：为什么这么说 | 不重复标题用词 | `limits.lead` |
| `h1` / `h2` / `h3` | 页面层级标题 | 不写成完整段落 | `limits.h1` 等 |
| `body` | 依据：事实、数字、步骤 | 不写感受、不写过渡句 | `limits.body`（整页） |
| `label` | 正文前缀（如「斜率」「余量」） | 不写整句，只做前缀 | `limits.label` |
| `kpi` | 一个数字 + 单位 | 不写解释，解释放 label | `limits.kpi` |
| `caption` | 图注：这张图在说什么 | 不写「如图所示」 | `limits.caption` |
| `source` | 出处：数据来源、口径、条件 | 不写致谢 | `limits.source` |
| `quote` | 引用原话 | 不改原话里的数字与判断 | `limits.quote` |

**触发条件**：同一页出现两个以上同类槽位。
**具体动作**：遵守**信息不重复**——标题说了的结论，正文只给依据；正文给了数字，图注只解释怎么看。
**常见错误**：标题 `成本下降 18%`，正文第一条 bullet 又写 `成本下降 18%`。重复不增加说服力，只增加字数。

## 4. 依据必须带数字与单位

**触发条件**：写任何一条 `body` / `kpi` / `caption`。
**具体动作**：一句话里至少出现一个可核对的量（数字 + 单位 + 口径），或一个可验证的动作（谁，做什么，何时）。
**常见错误**：`效率显著提升`（哪个量？提升了多少？跟谁比？）→ 改 `同样 32 W 负载下，结温从 78.1 降到 71.3 ℃`。

三个必须写清的口径：**比较对象**（跟谁比）、**条件**（在什么工况下）、**样本**（几条数据、几次实验）。

## 5. 结论前置，依据在后

**触发条件**：一页有 2 条以上依据。
**具体动作**：第一句给结论或取舍，后面的句子按「重要性降序」排列；不要按时间顺序排列，除非这一页的任务就是时间线。
**常见错误**：先讲三天怎么做实验，最后一句才说结论——听众在前 3 秒不知道要看什么。

## 6. 用户已提供文案时：只做适配，不改事实

**触发条件**：用户给了现成文案（PPT 原文、Word、口头要点）。
**具体动作**：只做三件事——① 按槽位拆分；② 按上限裁剪（删修饰词、删重复，**不删数字**）；③ 把话题名标题改成判断句，并**在审核表里标出改了哪一句**。
**常见错误**：顺手把用户的判断改软（`必然` → `可能`），或把用户的数字换成更好看的整数。这两件事都必须先问。

## 7. 用户没提供文案时：先出稿，不先出页

**触发条件**：用户没有文案，只给了主题或素材。
**具体动作**：先在 `records/copy-deck.md` 出**逐页文案稿**，交用户审核，通过后才进制作。稿子里每个由你推断出来的事实，行尾标 `[假设]`。
**常见错误**：直接开始做页，把文案当成排版过程中的副产品。这样的稿子改一次文案就要重排一次。

## 8. 长度自检（写完必做）

```
python scripts/copy_check.py --deck source/deck.json --out build/copy-report.md --json build/copy.json
```

脚本查的是**可计算的**部分：槽位字数、空话词表、AI 句式、句长、数字无出处、同页重复短语。它不判断「这句好不好」，那部分靠人读一遍，见 `workflows/06` 的 §6.5b。

## 9. 与既有阈值的关系

- 每页总字数 ≤ `density.maxCharsPerSlide`（220）；`copy.limits.body` 是文案稿阶段的上限，两者不一致时取**更严**的。
- 每行 ≤ `density.maxCharsPerLine`（34 个汉字）由版面决定，文案阶段只管「一句话别超过这个长度」。
- 标题字数 ≤ `type.maxTitleChars`（25），`copy.limits.h1` 与之保持一致。

## 检查清单

1. 每页标题都是可判断真假的句子，不是话题名。
2. 每页只有一个主张；两个主张就拆成两页。
3. 每条依据至少含一个数字 + 单位，或一个可验证动作。
4. 数字都写了比较对象、条件、样本（三者至少不缺前两个）。
5. 标题、正文、图注之间没有重复同一句话。
6. 所有槽位字数在 `thresholds.copy.limits` 之内（`copy_check.py` 无 CP-01）。
7. 用户提供的原话、数字、判断未被擅自改写；如有改写，审核表里逐条列出。
8. 由你推断的事实都标了 `[假设]`，且已交用户确认或按默认档处理。
9. `records/copy-deck.md` 的状态列已无 `[待确认]`，或未确认行已获用户书面默认。
10. 定稿文案已逐字进入 `deck.json`（没有在排版时二次改写）。
