# 本地偏好记忆（Local Preference Memory）

> 一句话：**当一版改到用户满意时，把"这个人喜欢什么"记在本机，下次直接从这里起步；只存本机，永不联网，启用前必须先问。**
> 跨形态通用：演示稿、文档、PDF、固定版面、图表、图片，都走同一套记录格式。

---

## 1. 三层前提（缺一条就不做）

| 前提 | 含义 | 违反的样子 |
|---|---|---|
| 用户满意之后才记 | 只记"用户明确认可的那一版"，不记中间稿 | 用户还在改第 3 轮，就急着总结他的偏好 |
| 只存本机 | 写入本机用户目录，不进仓库、不进网盘、不上传 | 把记忆文件放在仓库里跟着 git push 出去 |
| 启用前先问 | 首次启用、每次写入、每次导出，都要用户点头 | 偷偷记下来，用户下次发现"你怎么知道我喜欢这个" |

**触发条件**：用户说出以下任一句——"就这样""可以了""这版满意""不用再改了""就这版交付"。
**具体动作**：先用三行交回合问一次（见 §2），得到同意后再写入；没同意就什么都不写。
**常见错误**：把"机检 0 条"或"我改完了"当成用户满意，据此记偏好。

---

## 2. 询问方式（三行交回合，不许藏在末尾）

```
① 已做：v3 已按你的三条意见改完，机检 0/0/0/0，图在 build/contact-sheet.png
② 要你答：要不要把这次的偏好记到本机？（只存本机、随时可删、不上传）
   - 记（默认档：只记措辞与版式偏好，不记内容）
   - 不记
③ 不回则默认：不记（下次从零开始）
```

用户说"记"之后，还要把**准备写入的条目原文**给他看一眼再写——因为偏好记录会长期影响后续判断，写错比不写更糟。

---

## 3. 记什么、不记什么

### 3.1 记这七类（每条一句话，可判定）

| 类别 | 记录示例 | 为什么值得记 |
|---|---|---|
| 文案语气 | "标题偏爱判断句，不接受话题名；正文允许长句但单句不超过 40 字" | 下次起草直接对齐 |
| 信息密度 | "每页 3–5 个文本块；超过 6 个会被要求删" | 决定版式选择 |
| 配色倾向 | "底色偏纸感浅色；强调色只用一处；不接受紫色系" | 直接当 tokens 初值 |
| 字体偏好 | "中文用思源宋体做标题；英文等宽用于数据" | 免去反复试字 |
| 版式节奏 | "连续两页同版式会被指出；喜欢图页与文字页交替" | 决定节奏编排 |
| 表达禁忌 | "不要用'赋能/闭环'；不要写'研究表明'除非有出处" | 文案机检的个性化补充 |
| 交付方式 | "要 pptx + pdf 两份；文件名带日期；源文件要一起给" | 交付环节不再问 |

### 3.2 绝不记这些

- 项目事实与数据（那是项目文件的事，不进偏好库）
- 真实客户名、联系人、价格、未公开指标
- 用户粘贴的他人素材原文、图片原图
- 账号、token、内网地址、任何凭据
- 用户没有明确认可的推断（"他大概喜欢深色"）——**推断不记**

`scripts/pref_memory.py` 对 `rawText / fullText / credentials / apiKey / secret / customerName / personalData` 等字段直接拒收。

---

## 4. 存在哪、长什么样

- 默认目录：`~/.design-memory/`（Windows 为 `C:\Users\<你>\.design-memory\`）
- 三个文件：
  - `config.json`：`enabled` / `consentedAt`（启用时间）/ `defaultDir`
  - `entries.jsonl`：一行一条，机器读
  - `preferences.md`：同一批条目的中文可读版，给人看
- **脚本拒绝写入任何 git 仓库内的路径**（从目标目录向上找 `.git`，命中即退出并提示换目录）

条目结构（字段含义见 `templates/preference-entry.md`）：

```json
{
  "id": "mem-20261115-1432",
  "created": "2026-11-15T14:32:10+08:00",
  "project": "career-deck-revamp",
  "kind": "deck",
  "satisfiedVersion": "v3",
  "preferences": [
    {"area": "文案语气", "statement": "标题用判断句，不用话题名", "source": "user-said", "confidence": "high"},
    {"area": "信息密度", "statement": "每页 3–5 个文本块", "source": "observed", "confidence": "medium"}
  ],
  "avoid": ["不要用'赋能''闭环'这类词", "不接受紫色系"],
  "evidence": "用户原话：'标题要能看出结论'；第 4 页要求删掉一条 bullet"
}
```

`source` 只两种：`user-said`（用户说过的，可信）与 `observed`（我从改动里看出来的，中等可信）。`confidence` 用 `high/medium/low`，`low` 的默认不进建议。

## 5. 下次怎么用（不许擅自套用）

1. **阶段 0 开场读一次**：`pref_memory.py --list`，只读不回传。
2. **提出选项时**把偏好作为**默认档**，并明确说来源：
   > "你上次记录过：标题偏好判断句（第 2 页你改过一次）。这次默认按判断句写，要改回话题名告诉我。"
3. **用户否决一次，就当该条降级**：同一条被否 2 次 → 写回 `confidence: low` 或直接 `--forget`。
4. **不许把偏好当事实**：偏好只影响"怎么表达"，不影响"说什么"。
5. **跨项目不串味**：`kind` 不同的记录默认不互用（演示稿的密度偏好不必套到 A4 文档上），要用就明说。

---

## 6. 用户随时可以查、可以删

```bash
python scripts/pref_memory.py --status          # 是否启用、几条、目录在哪
python scripts/pref_memory.py --list            # 逐条看
python scripts/pref_memory.py --export-md       # 导出一份中文可读清单
python scripts/pref_memory.py --forget mem-…    # 删单条
python scripts/pref_memory.py --disable         # 停用（条目保留）
```

删除即时生效：`entries.jsonl` 与 `preferences.md` 同步重写，没有回收站副本。

---

## 7. 隐私与边界（写进交付说明的两句话）

1. "偏好记录只存在本机 `~/.design-memory/`，不上传、不同步、不含项目事实与个人信息。"
2. "任何一次写入前都会把条目原文给你看；不想要就说'不记'，已有记录可以说'删掉那条'。"

红线：**不把偏好当推荐算法**——不做"猜你还喜欢"，不做跨用户聚合，不做任何形式的导出到网络。本 skill 没有服务端。

---

## 检查清单

- [ ] 只在用户明确表示满意之后才提议记录
- [ ] 询问用的是三行交回合，默认档是"不记"
- [ ] 写入前把条目原文给用户看过
- [ ] 记忆目录在仓库之外（脚本已拦 `.git` 路径）
- [ ] 条目里没有事实数据、客户名、凭据、他人素材原文
- [ ] `source` 标了 `user-said` 还是 `observed`，`low` 的不进建议
- [ ] 下次使用时说明了"依据本地偏好记录"，并允许用户当场推翻
- [ ] 交付说明里写了隐私边界两句话
