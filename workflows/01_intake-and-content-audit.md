# 01 内容收集与审计

把用户提供的散料变成一张可被 02 阶段消费的内容卡。本步不设计任何页面，不选版式，不定配色。

## 输入

| 输入项 | 具体来源 | 必需 |
|---|---|---|
| 需求确认书 | `../discovery/requirement-summary.md` 的实例 | 是 |
| 用户原始材料 | 文字稿、旧 PPT/PDF/Word、数据表、图片 | 至少 1 件 |
| 参考作品拆解 | `../discovery/reference-analysis.md` | 否 |
| 约束值 | 时长、页数范围、页面比例、交付格式 | 是 |
| 用户禁忌 | 确认书「视觉偏好」段里的明确否定项 | 否 |

## 前置条件

- 需求确认书的「主题 / 受众 / 目的 / 场景 / 时长」5 项均有值。任一项为空，退回 `./00_requirement-discovery.md` 的提问步骤补齐，再回到本步。
- 材料可读取：文本可复制、图片可打开、表格有表头。扫描件 OCR 失败时记入缺失信息，不臆测数字。
- 已确认本次以中文为主、不做跨语言重写；若需双语，先与用户确认，再在页面任务里按双语版重算字数上限。

## 操作步骤

1. **文件盘点**。逐件登记：文件名、格式、页数或字节数、可读取状态、可信度（用户提供 / 用户转录 / 第三方公开）、拟用位置。判据：输入文件 100% 出现在表中，可信度无空值。产出：文件盘点表。
2. **抽取显式要求**。按主题、用途、受众、时长、页数、语言、比例、软件、交付格式 9 项逐一填写。判据：9 项全部有值，或标「未指定」并附一条假设。产出：需求 9 项表。
3. **四分类标注**。每段材料打且只打一个标签：事实（可核验的数值、日期、名称、已发生结论）、观点（评价与判断）、计划（未来时才）、推测（无来源预期）。判据：计划与推测的标注率 100%，事实条目必须带来源列。
4. **结构化拆解**。拆到 7 层：主题 → 章节 → 论点 → 证据 → 数据 → 案例 → 结论。判据：每个论点至少 1 条证据，否则标「证据不足」；每个数据带单位与口径（时间范围、样本量）。产出：内容骨架表。
5. **四类处置标注**。骨架每行标一个：必须保留 / 可压缩 / 重复 / 缺口。判据：必须保留项 ≤ 页数上限 × 3（每页最多承载 3 个保留事实）；重复项写清与哪一行重复；缺口项写清「影响哪个结论」。
6. **叙事类型判定**。从 7 类里选 1 主类型 + 最多 1 辅助类型：问题—解决方案 / 时间发展 / 论点—证据 / 产品功能 / 研究过程 / 个人成长 / 方案比较。判据：判定依据必须写「证据形态 + 时间轴 + 对比对象」三项，只写类型名不算完成。
7. **冲突清单**。材料与确认书冲突时一律以确认项为准，冲突单列成表，不自行裁决。判据：每条含「材料说法 / 确认项说法 / 影响页」。
8. **缺口提问**。仅当缺口会改变叙事类型或必须保留项时才提问，一次 ≤ 5 个；否则写下假设继续，假设进简报。

### 三条执行规则

**规则 1｜冲突让位**
**触发条件**：材料与需求确认书对同一事实给出不同数值、状态或日期。
**具体动作**：以确认项写进简报，同时在「冲突」段留一行「材料说 A / 确认项说 B / 影响 s07」，并在该页 notes 提示用户复核。
**常见错误**：取平均、取较新的一条、或两条都写进简报，导致 06 阶段无法判定哪个是权威值。

**规则 2｜计划不写成已完成**
**触发条件**：材料出现「将、计划、预计、目标、拟」等未来时才。
**具体动作**：挪进简报「计划与待达成」段，页面证据区不引用；必须展示时动词用「计划」，且同页给出当前值。
**常见错误**：把「预计提升 30%」写成「提升 30%」，06 阶段按内容核验直接判 P0。

**规则 3｜素材缺口不补图**
**触发条件**：某论点需要真实照片或截图，但材料中不存在。
**具体动作**：在简报「缺失信息与假设」写明缺什么、影响哪几页；处置只允许三种：换结构图 / 换信息图、删该论点、向用户索取。禁止用生成图冒充实拍。
**常见错误**：用示意插画代替产品实拍却标为实拍，属于内容造假，交付后无法修复。

### 页面必要性判据（决定删页，别等用户说「这页多余」）

**规则：一页一个观众问句**
- **触发条件**：排页数、写 `deck-outline.md` 时。
- **具体动作**：给每页写一个「观众会问的问题」，问句不得重复；两页问句相同就合并，某页写不出问句就删。判据：页数 ≤ 问句数，且每个问句在规划表里有对应页。
- **常见错误**：把材料按章节平铺成页，出现「过渡页」「补充说明页」这类没有独立问句的页——用户看完第一句话就是「这页是不是多余」。

**规则：删页三问**
- **触发条件**：页数超出上限，或用户说「太多了」。
- **具体动作**：按顺序问：① 这页的结论是否已在别页出现过？② 去掉它，叙事会不会断？（不会就删）③ 能否压成上一页的一条 `source` 或 notes？（能就压）
- **常见错误**：靠缩字号、加元素硬塞，把两页并成一页超密版，DEN-01 / DEN-02 立刻超限。

## 判断与分支

| 条件 | 动作 |
|---|---|
| 确认书缺受众或目的 | 退回 `./00_requirement-discovery.md`，补齐后再进本步 |
| 材料总页数 > 目标页数 × 3 | 先按步骤 5 压缩；压缩后仍超，与用户确认删减范围 |
| 任一论点证据 = 0 条 | 标「证据不足」，进 02 前回问一次；用户不补则从必须保留项删除 |
| 判不出唯一主叙事类型 | 留 2 个候选写入简报「待定」，由 04 阶段的页面任务清单裁决 |
| 用户指定风格与叙事类型冲突 | 记录冲突，02 阶段给转化方案，不改叙事类型 |
| 材料含受限内容（客户名单、未公开财务） | 标「需脱敏」，页面只保留聚合值 |
| 关键数字只有口头来源 | 标「待用户书面确认」，06 阶段按 P1 挂起 |

## 输出文件

项目目录结构在 00 阶段定好，本步只往里面写文件，路径均相对项目根 `<project>/`：

- `<project>/records/project-brief.md`：按 `../templates/project-brief.md` 填写，15 个字段全填。
- 简报附录（同一文件内）：文件盘点表、内容骨架表、冲突清单。
- 待用户确认清单：≤ 5 条，每条带默认假设，写在简报末尾。

## 完成标准

- 15 个字段无空值，空值必须写成「未指定」并附一条假设。
- 事实条目 100% 带来源；计划与推测 100% 不与事实混排。
- 每个必须保留事实都能指到原文位置（文件 + 页码或段落），命中率 100%。
- 页数范围与时长相容：页数 = 时长(min) ÷ (0.75–1.25 min/页)，结果落在确认书区间内。
- 冲突清单条数 = 实际冲突数，且每条有「影响页」。
- 待确认问题 ≤ 5 个，每个写明「不答时的默认假设」。

## 失败处理

| 类别 | 具体处理 |
|---|---|
| 缺素材 | 记入「缺失信息与假设」，给 3 个替代表达（结构图 / 数据表 / 删除该论点），不生成假素材；等待期继续推进 02 |
| 缺数据 | 数据位留「待补」并标来源类型，不估算、不用行业均值代替；04 阶段该页改为定性结论 |
| 工具不可用 | 文件加密、损坏或为纯扫描件时，记录格式与失败原因，请用户导出纯文本或截图；不猜内容 |
| 内容冲突 | 以确认项为准 + 冲突清单 + 页面 notes 提示；冲突超过 5 条时暂停，整批回问用户 |

## 检查清单

- [ ] 文件盘点表行数 = 实际输入文件数，可信度列无空值
- [ ] 9 项显式要求全部有值，或标「未指定 + 假设」
- [ ] 计划/推测条目与事实条目分栏存放，无混排
- [ ] 每个论点证据条数 ≥ 1，不满足的已标「证据不足」
- [ ] 数据 100% 带单位，且口径（时间范围 / 样本量）可查
- [ ] 必须保留项数量 ≤ 页数上限 × 3
- [ ] 叙事类型 = 1 主 + ≤ 1 辅，且写了三项判定依据
- [ ] 冲突清单每条含「材料说法 / 确认项说法 / 影响页」
- [ ] 待确认问题 ≤ 5 个，每个有默认假设
- [ ] 简报 15 个字段无空值
