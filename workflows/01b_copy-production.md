# 阶段 1.5：文案生产与审核（Copy Production）

> 主线位置：**阶段 1 内容审计之后、阶段 2 方向选择之前**。上游给"要讲什么"，本阶段给"每页写什么字"，下游拿定稿文案去选方向、排版面。
> 参考：规格 [`../references/copywriting-patterns.md`](../references/copywriting-patterns.md)、去 AI 味 [`../references/copywriting-antislop.md`](../references/copywriting-antislop.md)、载体 [`../templates/copy-deck.md`](../templates/copy-deck.md)。

## 0. 什么时候必须走这一步

**触发条件**：满足任意一条。

1. 用户没提供文案，只给主题、素材或一句话需求。
2. 用户提供了材料（旧 PPT、Word、报告、口头要点），但没有可直接进版面的句子。
3. 用户提供了完整文案，但字数、层级与目标版面明显不匹配。

**具体动作**：走本阶段的 S1–S10。

**什么时候可以跳过**：用户给的就是逐页定稿文案，且字数在阈值内。此时只走 S3（拆槽位）与 S6（请用户确认），并把 `records/copy-deck.md` 头部的 `来源` 写成 `用户原文`。

**常见错误**：把它当成"润色一步"。它是**一个阶段**：有产物、有门禁、不过不放行。

## 1. 输入与前置

| 输入 | 从哪来 | 缺了怎么办 |
|---|---|---|
| 受众与场合 | 阶段 0 的 `records/requirement-summary.md` | 缺就回阶段 0 问，不许猜 |
| 页数目标与每页任务 | 阶段 1 的 `records/deck-outline.md` | 缺就先做阶段 1 |
| 素材与事实清单 | 用户材料、`source/assets/` | 缺就走下方"素材授权"（阶段 0 的 S0b） |
| 语气与称呼 | 阶段 0 的五维探索 | 缺就用默认档：第三人称、不用"我们"、不用感叹号 |

## 2. 步骤

### S1 判定文案来源（一句话，先定性）

| 情况 | 判定 | 下一步 |
|---|---|---|
| 用户逐页给了定稿文案 | `来源=用户原文` | 直接 S3 |
| 用户给了材料但没有可用句子 | `来源=材料改写` | S3 → S4 |
| 用户只有主题 | `来源=从零生成` | S3 → S4 |
| 用户说"你看着办" | `来源=从零生成` + 默认语气档 | S3 → S4，并在交付时说明假设 |

### S2 需求不明确时：回阶段 0，不要在这里硬写

**触发条件**：不知道受众是谁、不知道讲多久、不知道结论要落在哪。
**具体动作**：回 [`00_requirement-discovery.md`](00_requirement-discovery.md)，只问**与本阶段相关**的三问（受众 / 时长 / 结论文案希望听众带走哪一句），然后按"三行交回合"结束本轮（已做 / 要你答 / 不回则默认）。
**常见错误**：带着模糊需求写 20 页文案，用户看完说"不是给这批人讲的"。

### S3 拆槽位：先搭骨架，再写字

**触发条件**：开始写任何一句。
**具体动作**：复制 [`../templates/copy-deck.md`](../templates/copy-deck.md) 到 `records/copy-deck.md`，逐页填**槽位名**（coverTitle / lead / h1 / body / caption / source / kpi / label / quote），先只写每页的**一句话主张**，不写正文。
**常见错误**：直接写正文。结果是每页都写到 150 字，装不进版面。

### S4 出首稿

**具体动作**：

1. 按 [`copywriting-patterns.md`](../references/copywriting-patterns.md) 的槽位分工与字数上限写。
2. 每页正文 ≤ 6 条依据，每条一个事实。
3. 由你推断出来的事实（不是用户给的、也不是素材里有的），行尾标 `[假设]`。
4. 需要用户确认的取舍（删哪一页、把哪句改软），写在 `records/copy-deck.md` 末尾的「待确认」区，**不要埋在正文里**。

**常见错误**：把 `[假设]` 藏在心里不标。用户审稿时看不出哪句是编的，后面就会当成事实用。

### S5 自检（机器能查的部分）

```bash
python scripts/copy_check.py --deck records/copy-deck.json --out build/copy-report.md --json build/copy.json
```

或对已有 deck：`python scripts/copy_check.py --deck source/deck.json ...`

要求：`CP-01`（槽位超字数）、`CP-02`（空话短语）、`CP-04`（AI 句式）、`CP-07`（数字无出处）为 0。其余项按报告逐条判断。

### S6 交用户审核（这一步不许跳）

**触发条件**：首稿与自检报告都已就绪。
**具体动作**：按"三行交回合"发给用户，并附 `records/copy-deck.md` 与 `build/copy-report.md`：

```
① 已做：23 页文案首稿，含 7 处 [假设]、3 处待你定的取舍；机器自检 0 项阻断。
② 要你答：语气是「对评审讲」还是「对客户讲」？第 9 页的 3 条依据删哪条？
   不回则默认：按「对评审讲」+ 保留前 2 条依据处理。
③ 下一轮：把 23 页逐页过一遍，你打勾的我冻结，你改的我按最小改动改。
```

**常见错误**：
- 把文案塞进 PPT 让用户"看成品再提意见"——改一处要重排一处。
- 只说"请确认"，不给默认档——用户不回，流程就卡住。

### S7 合并意见（最小改动）

**触发条件**：用户逐页给了 `[改]` / `[删]` / `[加]`。
**具体动作**：只改被指到的行；不改的行保持原样；每行状态更新为 `[已确认]`；改动记录写进文件末尾「修订记录」（第几轮、改了哪页、为什么）。用 diff 自查：**没被指到的页，全文 diff 必须为空**。
**常见错误**：借一次修改顺手润色其他 12 页。用户会发现"我只让改第 4 页"。

### S8 降 AI 味（若用户提到"像 AI 写的"）

**触发条件**：用户说"读着像 AI""太官方""不像人话"（**由用户发起**）；或你数出 §2 的可数事实后，把它们列给用户、由用户决定要不要处理。

**先明确两条**：
1. **"像不像 AI"不由我判定**。我只把可数事实和位置摆出来，判断由用户下（`copywriting-antislop.md` §1、§2）。
2. **"我自己润色一遍"不是一条路径**。同一个模型对"像 AI"的判断和它的生成偏好同源，自己改等于没改。修复必须交给外部。

**具体动作**：按 [`copywriting-antislop.md`](../references/copywriting-antislop.md) §3 的优先级走：

1. **P1 宿主已有 skill**——先查用户环境里有没有润色/去 AI 味 skill（本机常见 `humanizer-zh`）。有就**读它自己的 `SKILL.md` 按其流程执行**，小批（≤6 页）试改后对照。不改它的规则、不替它发挥。
2. **P2 联网找开源工具**——宿主没有，就先问第 4 节 Q37「允许我联网找并安装一个开源工具吗」。**未获许可不得检索、不得下载、不得安装**。获许可后按 §4 五条硬条件筛出 2–3 个候选（给仓库、stars、最近提交、许可、形态），用户点头再动手；装完把仓库 + commit + 许可写进 `assets/licenses.md`。
3. **P3 换模型改写**——用户愿意把文本交给第二个模型时，用 [`../templates/copy-crosscheck-prompt.md`](../templates/copy-crosscheck-prompt.md) 出交接包（每批 ≤12 页），**只传两件**：用户要求（受众/场合/语气/人称/用词禁忌/必须逐字保留项）+ 输出契约（直接给完整文案表格、不写建议理由、不标改动处）；另附各槽位字数上限作为版面物理限制。**本 skill 的句式规则、空话与 AI 句式清单、机检项一律不传**——它们是收回后的验收尺，不是发送前的笼子；我标的"哪几句像 AI"也不传，判断权在用户。它回的是成品：按「页 + 槽位」覆盖进 `records/copy-deck.md`，未改动的槽位原样保留；行数或槽位数对不上就整批退回重跑，不许自己补。

P1 不可用、用户又不同意 P2 → 直接 P3。**不许在 P1/P2/P3 都不成立时偷偷自己改，然后声称"已去 AI 味"。**

无论走哪条，改完都**不写「已通过」**：把改前/改后并排摊开，按 `copywriting-antislop.md` §5 问用户三个问题（像不像 AI / 具体哪几句 / 这版接受吗），把答复与"走哪条、为什么、改了哪些句"一起写进 `records/copy-antislop.md` 与「修订记录」。用户不回就记 `[假设]`，交付说明里点名"文案未经用户验收"。

**常见错误**：① 自己改了一遍就说"已处理"；② 未问用户就联网搜索并 `pip install` / `npx` 安装；③ 走 P3 却只要「建议」不要成品（拿到一堆建议又变成自己改）；④ 给第二个模型重写却漏了必须保留项（数字被改掉，取舍被改成骑墙话）；⑤ 把自己的句式规则、禁用词表、机检结果一起发过去——它只会照着模仿或绕词，产出仍是同一个模子。

### S9 定稿冻结

**触发条件**：所有页状态为 `[已确认]`，或未确认行已由用户默认。
**具体动作**：文件头部写 `状态: 已冻结 / 版本: v2 / 冻结时间`；此后 `deck.json` 里的每一句文本都必须逐字来自这份稿子，**不允许在排版时二次改写**。
**常见错误**：排版时发现"这句话太长放不下"，顺手压成另一句。此时应回到本阶段改稿，而不是在 `deck.json` 里改。

### S10 交接给阶段 2/4/5

**具体动作**：在 `records/deck-outline.md` 每页补一列"文案版本"，指向 `copy-deck.md` 的版本号；阶段 5 写 `deck.json` 时按页抄录。

## 3. 门禁（C1–C6）

进入阶段 2 之前，六条全过：

| # | 判据 | 证据 |
|---|---|---|
| C1 | 每页有且只有一个主张 | `copy-deck.md` 每页「一句话主张」列非空 |
| C2 | 每页标题是可判断真假的句子 | 抽查 5 页，命题化 |
| C3 | 槽位字数在阈值内 | `copy_check.py` 无 CP-01 |
| C4 | 空话与 AI 句式清零 | `copy_check.py` CP-02/CP-04 = 0 |
| C5 | 数字都有出处或标注「演示数据」 | 无 CP-07；`source` 列非空 |
| C6 | 用户已审核（或已按默认档处理并告知） | `copy-deck.md` 状态列全 `[已确认]`，或头部记录了默认档 |

**任一条不过 → 不进入阶段 2。** 视觉方向定完再回改文案，等于把阶段 2–3 的产出作废。

## 4. 失败与降级

| 情况 | 处理 |
|---|---|
| 用户说"你先写，我最后一起看" | 允许，但 `[假设]` 必须标；进入阶段 2 前仍是 C6 未过，只能做到阶段 3 的草案，不得进阶段 5 生产 |
| 用户不肯给受众/时长 | 用默认档（内部评审、每页 25 秒）+ 在交付说明里写明假设 |
| 页数装不下文案 | 先删依据（保留结论与最有力的一条），不缩字号；删掉的记入「待确认」 |
| 文案与素材冲突（说的和图上不一致） | 以**素材里的真实事实**为准，改文案，并在修订记录里写"依据素材改了第 X 页" |
| 涉及未公开数据/涉密 | 停下来问，不许代为脱敏或改写口径 |
| 多语言（中英双语） | 先定中文母版，再整页翻译；英文按同一槽位上限的 0.8 倍控制长度 |

## 5. 这个阶段对其它产出形态同样适用

v2 起新增的文档（Word/PDF）、固定版面（A4 海报/单页）、既有 PDF 改版，**文案部分一律走本阶段**：

| 形态 | 差异点 |
|---|---|
| 演示稿 deck | 每页一句话；上限按 `copy.limits` |
| 文档 doc（Word/PDF） | 段落而非槽位；追加"章首小结、图表标题、脚注"三类；不计每页字数，改查每段 ≤ 4 句 |
| 固定版面（海报/单页） | 只有标题 + 副标题 + 3–5 个信息块；文案总量更少，但每句更短 |
| 既有 PDF 改版 | 只改被遮罩/覆盖区域里的文字；**原 PDF 里没被覆盖的文字一个字都不许动** |

## 检查清单

1. `records/copy-deck.md` 存在，头部写了来源、语气、版本、状态。
2. 每页有一个「一句话主张」，且是判断句。
3. 槽位拆全，没有把正文塞进标题。
4. `copy_check.py` 的 CP-01/02/04/07 为 0。
5. 每页正文 ≤ 6 条依据，每条一个事实。
6. 所有推断事实标了 `[假设]`，且已确认或按默认档处理。
7. 用户意见合并时没改到未被指到的页（diff 为空）。
8. 若做了降 AI 味：路径与改动写在修订记录里。
9. 状态列无 `[待确认]`，或未确认行有书面默认。
10. `deck.json` 的文本与定稿逐字一致（抽查 3 页）。
