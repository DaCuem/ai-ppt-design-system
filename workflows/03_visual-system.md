# 03 建立视觉系统

把 02 选定的方向固化成一套可被 `source/deck.json` 直接读取的令牌。本步产出的不是风格说明，而是 5 组令牌 + 每组的合格判据。做完本步，任何一页都不再讨论「用什么颜色/字体」。

## 输入

| 输入项 | 来源 | 必需 |
|---|---|---|
| 项目简报 | `<project>/records/project-brief.md` | 是 |
| 主方向 8 栏 + 评分 | `<project>/records/design-proposal.md` | 是 |
| 可用字体清单 | 本机实测字体（见 `../docs/environment-report.md`） | 是 |
| 阈值真值 | `../schema/thresholds.json` | 是 |
| 令牌契约 | `../schema/deck.schema.json` 的 `tokens` 定义 | 是 |

## 前置条件

- 02 已定主方向：总分 ≥ 24、无单项 ≤ 2 分；未定则退回 `./02_style-selection.md` 步骤 5。
- 已跑 `python scripts/probe.py` 并确认「字体」栏至少列出 1 个中文字体；无则改用回退链首项为系统内置字体（如 SimHei）。
- `tokens` 目标文件位置已定：`<project>/source/deck.json`。

## 操作步骤

### 3.1 色彩系统

必须输出的字段：`bg`（主背景）、`bgAlt`（次背景，深/浅页用）、`primary`、`secondary`、`accent`、`fg`、`fgMuted`、`warn`、`ok`、`chartSeq`（图表色序 4–6 个）、面积占比（60/30/10）、深色页启用条件。全部为 `#RRGGBB`。

判定合格的标准：
- 正文 `fg` 对 `bg` 对比度 ≥ 4.5:1；大字（≥ 24 pt 或粗体 ≥ 18.66 pt）≥ 3:1。
- 色相数 ≤ 3；除黑白灰外主色饱和度 ≤ 0.85。
- `accent` 面积占单页 3%–15%，全 deck 只对应 1 类语义（重点 / 警示 / 峰值，三选一，不可混用）。
- 不得只写 `#000000` 与 `#FFFFFF` 两色；`chartSeq` 相邻两色明度差 ≥ 15%（0–100 亮度值）。
- 深色页与浅色页各有一套 `bg`+`fg` 配对，禁止在深底上用 `fgMuted` 当正文。

**规则：先定面积再选颜色**
**触发条件**：开始填 `tokens.colors`。
**具体动作**：先按 60/30/10 划面积，再从候选色板取色；`accent` 面积压在 3%–15%。
**常见错误**：先挑喜欢的颜色再摊面积，结果强调色占 40%，全篇没有唯一焦点。

### 3.2 字体系统

必须输出的字段：`display`（标题族）、`body`（正文族）、`mono`（数字/代码，可选）、`fallback` 回退数组、字重表、字号阶梯（对应 `tokens.type` 的 11 个 role：coverTitle / h1 / h2 / h3 / lead / body / caption / source / pageNumber / kpi / label）、行距区间、中英混排规则。

判定合格的标准：
- 字族 1–3 个；`display` 与 `body` 可是同一族的不同字重。
- 字号全部落在 `thresholds.type.minPt` 之上：h1 ≥ 36、h2 ≥ 24、h3 ≥ 20、body ≥ 16、caption ≥ 11、pageNumber ≥ 9（单位 pt）。
- 标题字重 ≥ 700；正文 400；强调 ≤ 2 种字重，禁止靠 5 种以上颜色制造层级。
- 行距：标题 0.95–1.15，正文 1.25–1.55。
- 每行中文字数：正文 ≤ 34 字/行，注释 ≤ 48 字/行，一级标题 ≤ 16 字/行。
- 构建时同时写入 latin 与东亚字体两个槽位，否则中文会在 PowerPoint 里回退为宋体。字体缺失不阻断构建，只在 `render.py` 的 `missingFonts` 里告警，因此在 03 就要给可用的回退链。

### 3.3 网格与几何语言

必须输出的字段：栏数、栏间距、左右边距、上下边距、基线、线条粗细层级、圆角规则、页码位置、图形基本形态、图片裁切比例。

判定合格的标准（基准画布 13.333 × 7.5 in）：
- 12 栏；栏间距 0.2 in；左右边距 0.6 in；上下边距 0.45 in；基线 0.08 in。由此得内容区宽 12.133 in、单栏宽 0.828 in；换算式见 `./05_slide-production.md` 步骤 3。
- 线条只用 0.5 / 1 / 2 pt 三档，且每档有固定语义（分隔 / 描边 / 强调）。
- 圆角默认 0 in；出现圆角必须写明承载什么信息（如标签分组容器），否则按 `../references/anti-patterns.md` 对应条目判定。
- 页码：右下角，9–11 pt，`fgMuted`，位于安全边距内侧，距右 ≥ 0.6 in、距下 ≥ 0.45 in。
- 图片裁切只用 3:2、16:9、1:1 三种比例，同页混用 ≤ 2 种。

### 3.4 图像语言

必须输出的字段：图像类型（实拍 / 截图 / 结构图 / 图表 / 示意）、图像角色（证据 / 主体 / 背景 / 装饰）、处理规则（裁切、色调、边框、标注）、来源与许可记录方式、缺图处理。

判定合格的标准：
- 每页「背景 / 装饰」类图像 ≤ 1 个；作为证据的图像必须带 `alt` 与来源行。
- 同 deck 内图像色调处理一致：统一原色、统一去饱和至 ≤ 20%，二者只能选一。
- 缺图时允许的 3 种替代只有：结构图、数据表、删除该论点；不得用生成图冒充实拍。
- 许可记录写入 `assets/licenses.md`（仓库根或项目 `source/assets/` 内），格式为「文件名 / 来源 / 许可类型 / 是否可商用」。

## 判断与分支

| 条件 | 动作 |
|---|---|
| 正文对比度 < 4.5:1 | 只改色值，不降字号；改后重算全部页面配对 |
| 深色页与浅色页共用一套 `bg` | 增加 `bgAlt` 与配套 `fg`，并把深色页限制在该 1 类用途（如章节页） |
| 指定字体在本机缺失 | 写 2 级回退链；不得为了字体把整页栅格化 |
| 素材主色与主色冲突（同色系糊在一起） | 图像统一去饱和 ≤ 20%，或改用 1:1 裁切加 2 pt 描边分隔 |
| `accent` 出现第 2 类语义 | 拆成 `accent` + `warn`，或删掉一类强调 |
| 12 栏排不下所需信息块 | 改版式（回 04 换 L 编号），不缩栏间距；栏间距低于 0.16 in 即判不合格 |
| 品牌色本身对比度不足 | 品牌色只用于色块/图形填充，文字改用 `fg` |

## 输出文件

- `<project>/records/design-proposal.md` 追加「视觉系统」章：四块各一张「字段 → 取值 → 判据」表。
- `<project>/source/deck.json` 的 `tokens` 段落落盘，结构如下（字段含义即上述四块产出）：

```json
{"tokens": {
  "colors": {"bg": "#F5F2EC", "bgAlt": "#1C1F26", "fg": "#1C1F26", "fgMuted": "#5A5F6A",
             "primary": "#2F4858", "secondary": "#86A0A8", "accent": "#C25E3E",
             "ok": "#3F7D5A", "warn": "#A8522F"},
  "fonts": {"display": "Source Han Serif SC", "body": "Microsoft YaHei",
            "mono": "Cascadia Mono", "fallback": ["Noto Sans SC", "SimHei"]},
  "type": {"h1": {"size": 48, "weight": 700, "lineHeight": 1.1},
           "body": {"size": 18, "weight": 400, "lineHeight": 1.45}},
  "grid": {"cols": 12, "gutterIn": 0.2, "marginXIn": 0.6, "marginYIn": 0.45, "baselineIn": 0.08},
  "space": {"xs": 0.08, "sm": 0.16, "md": 0.24, "lg": 0.4, "xl": 0.64}
}}
```

- `tokens.colors` 键名即全 deck 唯一合法色名；`tokens.type` 的键名必须与元素 `role` 同名，否则回退到默认阶梯。

## 完成标准

- 四块产出的字段 100% 有值，无「待定」。
- `tokens` 通过 `../schema/deck.schema.json` 校验；`colors` 与 `type` 的键名能被 `scripts/qa_check.py` 的 COL-01（合法色名）、COL-02（字号在阶梯内）、COL-03（字族 ≤ 3）判定为通过。
- 所有文字与背景组合的对比度均 ≥ 4.5:1（大字 ≥ 3:1），且写到文档里的每个色对都能手算复核。
- 字号阶梯 11 个 role 全部 ≥ `thresholds.type.minPt`。
- 网格 5 个数值与 `thresholds.canvas.grid` 完全一致。
- 图像处理规则能回答「这张图放进来要不要改色调」这个问题，无需再问。

## 失败处理

| 类别 | 具体处理 |
|---|---|
| 缺素材 | 图像语言栏改为「结构图 + 数据表优先」，并写明缺图页改用 L08 / L10；不留空栏 |
| 缺数据 | 图表色序照常定义但标注「暂无数据，色序待实测后校验明度差」；不得先画图表占位 |
| 工具不可用 | `probe.py` 报告无中文字体时，回退链首项写系统内置黑体，并在 `../docs/environment-report.md` 记录缺字体事实；不声称已嵌入字体 |
| 内容冲突 | 品牌规范与对比度要求冲突时，品牌色只用于填充，文字用 `fg`；冲突与处置写入提案「需确认事项」 |

## 检查清单

- [ ] `tokens.colors` 含 bg/bgAlt/fg/fgMuted/primary/secondary/accent，且无纯黑白两色方案
- [ ] 正文对背景对比度 ≥ 4.5:1，大字 ≥ 3:1，逐对可查
- [ ] 色相数 ≤ 3，accent 面积 3%–15%，语义唯一
- [ ] 字族 1–3 个，字号阶梯 11 个 role 全部 ≥ 最小字号
- [ ] 标题字重 ≥ 700，正文行距 1.25–1.55
- [ ] 网格 = 12 栏 / 0.2 in / 0.6 in / 0.45 in / 0.08 in，与 thresholds 一致
- [ ] 线宽只有 0.5/1/2 pt 三档，圆角默认 0 in 且有例外理由
- [ ] 图像角色与处理规则可判定，同 deck 色调处理只有一种
- [ ] 缺图处置只出现结构图 / 数据表 / 删除论点三种
- [ ] `tokens` 通过 deck.schema.json 校验，键名与 role 对应
