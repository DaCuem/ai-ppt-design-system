# 06 质量检查与视觉诊断

对已渲染的整套页面做三类检查、一次自动扫描、一次逐页看图，把问题分级并写成可复算的 `qa-report.md`。本步的结论只有两种：通过（无 P0）或不通过。

## 输入

| 输入项 | 来源 | 必需 |
|---|---|---|
| deck 源 | `<project>/source/deck.json` | 是 |
| pptx 与预览图 | `<project>/build/deck.pptx`、`build/preview/slide-*.png` | 是 |
| 渲染清单 | `<project>/build/render-manifest.json`（含 `missingFonts`） | 是 |
| 简报与规划表 | `records/project-brief.md`、`records/deck-outline.md` | 是 |
| 阈值 | `../schema/thresholds.json` | 是 |

## 前置条件

- 05 已完成：`build_pptx.py` 与 `render.py` 均退出码 0；未完成退回 `./05_slide-production.md` 步骤 6。
- 预览图数量 = 页数，且从 `slide-01.png` 连续编号；不满足先重渲。
- `missingFonts` 非空时先解决字体，否则字形检查结果不可信。

## 操作步骤

### 6.1 内容检查（逐条判 是/否，8 条）

| 编号 | 检查项 | 合格判据 |
|---|---|---|
| C1 | 事实一致 | 与 `project-brief.md` 的必须保留事实逐条比对，改动 0 处 |
| C2 | 单位完整 | 页面数字 100% 带单位；图表 `unit` 非空（CNT-02） |
| C3 | 计划未写成已完成 | 未来时才的词后无「已完成/已实现」表述 |
| C4 | 结论可溯源 | 每个结论有页脚 `source` 或 notes 出处 |
| C5 | 标题即结论 | 每页 1 个标题、≤ 25 字、含动词或数值（CNT-04） |
| C6 | 专名一致 | 人名、机构名、产品名与简报逐字一致 |
| C7 | 结构完整 | 覆盖页与收尾页都存在，章节页序与规划表一致 |
| C8 | 归属正确 | 个人成果与团队成果分离，夸大 0 处 |

### 6.2 设计检查（8 条）

| 编号 | 检查项 | 合格判据 |
|---|---|---|
| D1 | 焦点唯一 | 每页第一眼落点 1 个，面积 ≥ 页面积 20% |
| D2 | 字号阶梯 | 标题:正文 = 1.3–3.0:1（TYP-02，阈值见 `schema/thresholds.json` 的 `type.titleBodyRatioMin/Max`） |
| D3 | 留白 | 留白 ≥ 25%（DEN-05） |
| D4 | 相邻不重复 | 相邻页 `layout`+`gridTemplate`+`focalPosition` 不全同（REP-01） |
| D5 | 版式分布 | 单一签名占比 ≤ 35%（REP-02） |
| D6 | 装饰有理由 | 每个装饰元素能说出承载的分组/刻度功能 |
| D7 | 图像不变形 | 裁切比例 ∈ {3:2, 16:9, 1:1}，无拉伸 |
| D8 | 图表可直读 | 直接标注数值 + 单位 + 来源，不靠图例猜 |

### 6.3 技术检查（8 条）

| 编号 | 检查项 | 合格判据 |
|---|---|---|
| T1 | 不越界 | 元素在画布内（GEO-01/GEO-02，容差 0.02 in） |
| T2 | 不溢出 | 文本所需高度 ≤ 框高 + 0.02 in（OVF-01/OVF-02） |
| T3 | 不重叠 | 文本块互不重叠，容差 0.05 in（OVL-01） |
| T4 | 字号下限 | h1 ≥ 36 / h2 ≥ 24 / h3 ≥ 20 / body ≥ 16 / caption ≥ 11 / 页码 ≥ 9 pt（TYP-01） |
| T5 | 对比度 | 正文 ≥ 4.5:1，大字 ≥ 3:1（CON-01） |
| T6 | 无障碍 | 每张图有 `alt`（CNT-01），图表有 unit+source（CNT-02） |
| T7 | 结构合法 | slide id 从 s01 连续递增、无重复（STR-01） |
| T8 | 产物一致 | 预览图数 = 页数；PDF 与 PPTX 页数一致；`missingFonts` 为空 |

### 6.4 自动检查：跑 qa_check.py

```bash
python scripts/qa_check.py --deck source/deck.json --out records/qa-report.md --json build/qa.json --thresholds schema/thresholds.json
```

- `--deck` 必填，只读 deck.json，不读 pptx；`--out` 省略只打控制台；`--json` 输出机器可读结果；`--thresholds` 省略时按脚本位置解析仓库内 `schema/thresholds.json`。
- stdout 每行格式：`P<级别> <slideId> <检查ID> <元素名> <中文描述，含实测值与阈值及单位>`；末行 `SUMMARY P0=n P1=n P2=n P3=n issues=n pages=n exit=0|1|2`。无问题时只有 SUMMARY 一行。
- 退出码：0 = 无 P0（P1 不阻断）；1 = 存在 P0；2 = 无法检查（输入不可读或非法）。
- 读法：先看 SUMMARY 的 P0/P1 计数，再按 slideId 看明细；同一检查 ID 多页出现 = 系统性问题，改 `tokens` 或版式，不逐页补。
- 实现细节以 `scripts/README.md` 与 `scripts/qa_check.py --help` 为准。

### 6.5 视觉检查：12 个观察点

按页看 `build/preview/slide-NN.png`（144 dpi），每页扫这 12 点：① 第一眼落点是否就是规划表的 `focalPosition`；② 标题是否 ≤ 2 行且无截断；③ 文本与图形间距是否 ≥ 0.2 in；④ 压在图片上的文字是否仍 ≥ 4.5:1；⑤ 图片裁切是否切掉主体（人脸、产品边缘、文字）；⑥ 图表坐标轴有无单位、图例是否多余；⑦ 页码位置是否每页一致；⑧ 留白是否 ≥ 25%；⑨ 与上一页是否一眼能区分；⑩ 11 pt 注释在 144 dpi 下是否可辨；⑪ 强调色是否只出现在该强调处；⑫ 中英混排的标点与间距是否正确。

再看 `build/contact-sheet.png` 扫全场节奏：连续 3 页以上构图相像即问题。

### 6.5b 内容级复核（人眼，必须做；机器绿 ≠ 内容成立）

`qa_check.py` 只能证明「框没超、字够大、对比度够」，证明不了「图里的东西成立」。交付前逐项过：

| 编号 | 检查项 | 合格判据 | 不成立的处置 |
|---|---|---|---|
| V1 | 生成图结构自洽 | 按结构清单逐项对：零件齐全、顺序正确、无悬空、无重复 | 重画或降档 |
| V2 | 2 倍放大复查 | 连接处、管口、边缘无碎屑、无幻影件 | 局部修补或重画 |
| V3 | 图与页面任务匹配 | 封面图能概括全片主题；证据页图能证明该页结论 | 换图或改版式 |
| V4 | 图注与事实一致 | 生成图标注「示意图（AI 生成）」，不与实拍混称 | 改标注或换图 |
| V5 | 每页有存在理由 | 能说出该页回答的观众问句；说不出就删页或合并 | 删页 / 合并 / 压成一条 source |

V1–V2 的方法与三类高频问题见 `references/imagery-guide.md` §5.2；V3 的图片角色映射见同文件 §1；V5 的问句判据见 `workflows/01_intake-and-content-audit.md`。

### 6.6 分级判定

| 级别 | 判定标准（满足任一即归该级） | 处置 |
|---|---|---|
| P0 | 文件打不开；关键事实/数字错误；文字溢出 > 框高 30%；元素出画布；内容缺页 | 阻断交付，必须修复并全量重渲 |
| P1 | 溢出 > 0.02 in；字号低于下限；对比度不足；相邻页版式重复；图表缺 unit/source；缺 alt；id 不连续 | 本轮必须修复 |
| P2 | 元素数 > 14；字数 > 220；标题 > 25 字；字号比越界；越安全边距；非法色名；字族 > 3 | 修复或写延期理由 |
| P3 | 容差内重叠；行数超限；焦点连续 3 页相同；缺页码；字号不在阶梯 | 可延到下一版，但需记录 |

`thresholds.qa.blockOnP0 = true`：存在 P0 时不得进入 07。

### 6.7 修复后必须重渲染

**触发条件**：`source/deck.json` 或 `source/assets/` 任一文件改动。
**具体动作**：重跑全链路 `build_pptx.py` → `render.py` → `qa_check.py`，刷新 `build/preview/` 与 `build/qa.json`，再在报告「复查」列写「已重渲 slide-NN，复查通过」。
**常见错误**：只改 deck.json 就说已修复；报告写「已修复」但预览图仍是旧的。

### 6.8 写 qa-report

按 `../templates/qa-report.md` 填：问题表 9 列（编号 / 页码 / 类别 / 严重程度 / 检查项 / 问题描述 / 修复建议 / 状态 / 复查）+ 分级统计行 + 结论行。`检查项` 一律用 6.4 的检查 ID（C1–C8 / D1–D8 / T1–T8 或脚本 ID）。问题描述必须含实测值与单位（例：`s03 h1 文本溢出 0.34 in，框高 1.40 in`）。自动生成的 6 列 md 需并入 9 列表，不得两表并存。

## 判断与分支

| 条件 | 动作 |
|---|---|
| 存在 P0 | 停止交付流程，修复后全量重渲，回 6.1 重查 |
| P1 数量 > 页数 × 0.5 | 判为系统性问题，改 `tokens` 或版式后全量重做，不逐页补 |
| 同一检查 ID 在 ≥ 3 页出现 | 按系统性缺陷处理，写入报告「根因」列 |
| `missingFonts` 非空 | 先换字体或补回退链，再重渲；不带着字体告警交付 |
| 预览图与 pptx 页数不一致 | 判 T8 失败（P1），重渲全量 |
| 用户要求「先看两页」 | 只渲指定页并标注「局部检查，未覆盖全场节奏」 |
| 只剩 P3 | 允许交付，报告结论写「通过（遗留 P3 n 条）」 |

## 输出文件

- `<project>/records/qa-report.md`：9 列表 + 分级统计 + 结论行 + 复查记录。
- `<project>/build/qa.json`：机器可读明细（`summary`、`issues[]`）。
- `<project>/build/preview/slide-*.png` 与 `build/contact-sheet.png`：复查依据，保留不删。

## 完成标准

- 三类检查 24 条逐条有结论，无「待看」。
- 12 个视觉观察点每页都过，问题都进了报告。
- P0 = 0 才写「通过」；P0 > 0 时结论必须是「不通过」。
- 每个修复项都有「复查」值，且复查发生在重渲之后。
- 报告中的实测值 100% 带单位，检查项 100% 用统一 ID。
- `qa_check.py` 退出码与报告结论一致（0 对应无 P0）。

## 失败处理

| 类别 | 具体处理 |
|---|---|
| 缺素材 | 缺图页判 P1（CNT-01 或证据不足），报告写替代方案；不因缺图跳过检查 |
| 缺数据 | 图表页判 P2，标「数据待补」；不填假数以通过 DEN 类检查 |
| 工具不可用 | `qa_check.py` 退出码 2 时，按 stderr 修 deck.json 或 thresholds；渲染不可用则报告标「未渲染验证，仅静态检查」，不得声称已看渲染图 |
| 内容冲突 | 报告结论与用户口径冲突 → 以用户确认项为准，冲突记入报告「待确认」段，不自行改结论 |
