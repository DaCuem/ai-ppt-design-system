# 项目需求卡 project-brief

用途：01 内容审计的产出，02–07 只认这一份事实来源。保存到 `<project>/records/project-brief.md`。

## 基本信息

| 字段 | 填写内容 | 填写提示 |
|---|---|---|
| 项目主题 | | 一句话说清做什么 |
| 使用场景 | | 现场、线上或评审会 |
| 目标受众 | | 人数与决策角色 |
| 演示目的 | | 看完后要做的动作 |
| 演讲时长 | | 分钟为单位，含问答 |
| 页数范围 | | 给区间，不给单值 |
| 页面比例 | | 默认 16:9，写换算英寸 |
| 语言 | | 中文、英文或双语 |
| 输出格式 | | pptx 与 pdf 是否都要 |
| 用户指定风格 | | 用户原话照抄，不改写 |
| 用户喜欢的参考 | | 写链接或本地文件名 |
| 用户明确不喜欢的元素 | | 越具体越好，写元素名 |
| 必须保留的内容 | | 删了会出事的原话 |
| 可用素材 | | 路径、数量、格式 |
| 事实风险待确认信息 | | 列出必须用户确认的项 |

## 填写示例（已填）

- 项目主题：国产工业相机 2026 春季新品发布路演，面向产线集成商。
- 目标受众：集成商 60 人、采购与技术负责人各 20 人，其中 8 人参与选型决策。
- 演讲时长：25 分钟，另留 10 分钟问答；页数范围 16–20 页。
- 必须保留的内容：原话「响应延迟从 12 ms 降到 4 ms」与第三方实验室实测报告编号。

## 自检

1. 15 个字段全部有内容，「待确认」不超过 3 项且都已列进事实风险栏。
2. 所有数字带单位（分钟、页、英寸、人、%），区间优先于单值。
3. 用户原话与规格原文逐字照抄，未改写、未合并、未润色。

## 检查清单

- [ ] 15 个字段无空缺，空白处已写「未提供」
- [ ] 演讲时长与页数范围可换算（约 1.2–1.5 分钟/页）
- [ ] 页面比例写明 16:9 与 13.333×7.5 in
- [ ] 用户原话用引号照抄，未改写
- [ ] 可用素材写清路径与数量
- [ ] 事实风险栏每条都有「需谁确认」
