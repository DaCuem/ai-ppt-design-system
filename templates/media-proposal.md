# 媒介立项说明模板

> 用途：任何人提出"我们也支持 X 格式吧"，先填这一页再讨论。
> 依据：`docs/lighthouse-plan.md` §6。**没有这一页，不允许开工，也不允许写进 README 的支持列表。**

## 一、十个必答问题

| # | 问题 | 本次回答 |
|---|---|---|
| 1 | 用户要完成的**实际设计任务**是什么？（不是文件扩展名） | |
| 2 | 该媒介的**独特设计问题**是什么？（响应式 / 分页 / 演示距离 / 出血 / 交互状态） | |
| 3 | 哪些设计知识可以**复用**？请指出具体条目，不许写"复用设计知识库" | |
| 4 | 哪些知识必须**新增**？（媒介专属规则） | |
| 5 | 源文件是什么？给出 Schema 或组件契约 | |
| 6 | 如何生成？builder / renderer 与输入输出 | |
| 7 | 如何检查？机器可检查项与人工复核项分别列出 | |
| 8 | 如何证明有效？基准任务、对照方案与评分方式 | |
| 9 | **不支持什么**？能力边界与降级策略 | |
| 10 | 什么时候算完成？可复现的验收标准与样例 | |

## 二、填写要求

**触发条件**：新增任何一种媒介（文档、固定版面、网页、表格、演示之外的第 N 种输出）之前。

**具体动作**：
1. 十个问题逐条写答案，不许留空；答不出来的那一条就是本次立项的真实风险。
2. 第 3 题必须点名具体文件与条目（例：`references/design-principles.md` 的"邻近"原则），并标注它属共享核心还是需改造。
3. 第 9 题必须写降级策略（例：不支持的图表类型 → 显式跳过并 rc=1，不静默降级）。
4. 第 10 题的验收标准要能被脚本或人按命令复现，不许写"效果好"。
5. 填完后在 `docs/decisions/` 开一条 ADR 引用本说明，再进入阶段 0 的准备。

**常见错误**：
- 把"能导出文件"当成立项理由——那只是工具，不是设计能力。
- 第 3 题只写"复用知识库"，未指出具体条目，导致实际开工时又从零写一套。
- 第 9 题留空，遇到第一个不支持的元素就临时加异常分支，最终边界不可预测。
- 借用其他媒介的 Schema 勉强适配（例如用绝对坐标的页面模型去做流式文档）。

## 三、否决条件（任一成立即不得立项）

1. 只有"能导出文件"的实现，没有设计决策流程与质量闭环。
2. 无法指出复用了共享核心的哪些具体条目。
3. 无法给出机器可检查项，只能靠"看着还行"。
4. 无法给出基准任务与对照方案，即无法证明它有效。
5. 需要把共享核心改造成某一种媒介专属（说明这条能力不具备通用性）。

## 检查清单

- [ ] 十个问题全部有答案，没有留空。
- [ ] 第 3 题点名了具体知识条目，并标注共享/需改造。
- [ ] 第 9 题写清了不支持项与降级策略。
- [ ] 第 10 题的验收标准可被命令复现。
- [ ] 已开对应 ADR 并在 `docs/decisions/README.md` 登记。
- [ ] 没有触发第三节任一否决条件。
