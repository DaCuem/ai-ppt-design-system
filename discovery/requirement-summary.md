# 需求确认书生成规范

需求确认书是阶段 0 的唯一交付物，也是后续所有设计决策的引用源。本文件规定三类记录怎么写、什么时候必须回退重问、冲突怎么分级、用户授权 AI 自主决定时怎么记，以及确认书本身的格式与长度。

模板文件见 [templates/requirement-summary.md](../templates/requirement-summary.md)，字段清单来自需求规范 §0.7。

---

## 1. 三类记录

每条记录都必须带标签、带来源。没有来源的记录等于没有记录。

| 类型 | 判定判据 | 写法 | 例 |
|---|---|---|---|
| `[已确认]` | 用户原话含明确选择、数量或"是 / 对 / 可以"；能引用原句或选择编号 | `[已确认] 字段：值（来源：用户原话 / 选择 n）` | `[已确认] 时长：8 分钟（来源：用户原话"8分钟答辩"）` |
| `[建议]` | 由 AI 提出，用户未回应或未反对 | `[建议] 字段：值（依据：__；待用户选择）` | `[建议] 视觉方向：深色封面 + 单焦点内页（依据：发布会参考；待选）` |
| `[假设]` | AI 为推进填的默认值，用户未表态 | `[假设] 字段：默认值（可改；触发条件：__）` | `[假设] 比例：16:9（未提及，按默认；可改）` |

**R1 沉默不等于确认**

**触发条件**：AI 提出方案或默认值后，用户未回应、只回"嗯"、或转向别的话题。
**具体动作**：保持 `[建议]` 或 `[假设]`，不得升格为 `[已确认]`；升格只允许两种凭据——用户原话引用、用户选择编号。
**常见错误**：AI 说"我用深色系"，用户回"继续"，下一版记录写成"已确认深色系"。用户反驳时，基于深色的 3 页作废。

**R2 一次确认只覆盖一条**

**触发条件**：用户对某条记录回复"可以 / 对 / 行"。
**具体动作**：只把该条升为 `[已确认]`，其余同批 `[建议]` 保持不变。若用户说的是"都行 / 你定"，按第 4 节授权流程处理，不是逐条确认。
**常见错误**：用户回了"可以"，AI 把整份 12 条建议一次性标成已确认。其中 9 条用户根本没看。

**R3 状态只降不升（无凭据时）**

**触发条件**：发现某条 `[已确认]` 与后来的信息矛盾。
**具体动作**：立即降回 `[待确认]`，在变更记录写"原值 → 新信息 → 待确认"，并回退到该条相关的决策点重问一次（见第 3 节）。
**常见错误**：为了保持确认书"看起来完整"，把矛盾信息悄悄抹掉，按旧值继续做。

## 2. 判定示例

| 用户说的话 | 正确记录 | 错误记录 |
|---|---|---|
| "大概 15 分钟吧" | `[已确认] 时长：15 分钟（来源：用户原话）` | `[假设] 时长：15 分钟` |
| "16:9 就行，其他你看着办" | `[已确认] 比例：16:9`；`[建议] 其余视觉参数（授权范围：视觉方向）` | `[已确认] 全部视觉参数` |
| "页数别太多" | `[假设] 页数：14 页（用户说"别太多"→ 按 1.2×时长取下限）` | `[已确认] 页数：14 页` |
| （用户未回复视觉方案） | `[建议] 深色封面，待选` | `[已确认] 深色封面` |
| "用我们品牌蓝" | `[已确认] 主色：品牌蓝（面积 60%）；` 追加 `[假设] 品牌蓝具体色值：待提供，先用 #1F4E79 占位` | `[已确认] 品牌蓝 = #1F4E79` |

## 3. 何时必须回退确认

**R4 六类回退触发**

**触发条件**：出现下列任一情况。
**具体动作**：停止推进，回到相关决策点重问 1 个问题（不是重开整轮），更新记录后继续。
**常见错误**：把冲突写进"风险"栏然后照原计划做。风险栏没人读，返工发生在交付前 2 小时。

1. 新信息推翻了某条 `[已确认]`（如用户后来说"其实是给外部客户看"）。
2. 冲突升级为阻断级（见第 4 节），且无法用默认值绕过。
3. 阈值不可行：按用户偏好排下去，正文会低于 16 pt、对比度会低于 4.5:1、或单页超过 220 字。
4. 用户改变涉及全局参数（色彩 / 字体 / 网格 / 比例），影响 ≥ 3 页。
5. 进入阶段 2（风格选择）前，仍有 ≥ 2 条影响视觉系统的 `[假设]` 未确认。
6. 制作中发现内容真实性存疑（数据来源不明、客户名未授权、截图含敏感信息）。

回退只问 1 个问题，句式固定："{字段} 现在是 {旧值}，你说的是 {新信息}，按哪个走？"——不要重发整份问卷。

## 4. 冲突分级

**R5 分级判据**

**触发条件**：用户需求之间、或需求与客观条件之间冲突。
**具体动作**：先判断"若不解决，是否会导致整套重做或交付后返工 ≥ 50% 页面"。是 → 阻断级，停下来要求用户裁决；否 → 可延后级，取默认值 + `[假设]` 继续。
**常见错误**：把所有冲突都当阻断，用户被反复打断；或把所有冲突都延后，交付时才发现页数与内容根本不匹配。

**阻断级（必须停，不得自行折中）**

| 冲突 | 判据 | 处理动作 |
|---|---|---|
| 时长与页数不匹配 | 每页可停留时间 < 25 秒 | 给 2 个方案（砍页 / 转附录），写明各自代价，请用户选 |
| 必保留内容与页数上限冲突 | 必保留条数 × 0.67 页 > 页数上限 | 列出"必须砍"的 3 条候选，请用户删 |
| 视觉偏好与素材条件冲突 | 要求图片面积 ≥ 40%，可用图 0 张 | 给"几何替代 / 降低图片占比 / 用户补图"三选一 |
| 涉密内容 | 用户要求展示但材料含客户名、未发布数据 | 停，确认脱敏方式后才可写入页面 |
| 技术不可行 | 输出格式/软件不支持指定效果（如依赖 PowerPoint 的动画） | 说明限制，给等价替代 |

**可延后级（记录后继续）**

| 冲突 | 处理 |
|---|---|
| 指定字体不可用 | 用回退链替代（Microsoft YaHei → Noto Sans SC → Deng），记 `[假设]` |
| 用户偏好色与品牌色冲突 | 品牌色作主色（60%），偏好色作强调色（≤ 15%） |
| 页数超出上限 10–20% | 先按上限做，把多出的页列为"候选删除"，交付前确认 |
| 参考作品的品牌元素不可用 | 保留结构，替换语言（见 [reference-analysis.md](./reference-analysis.md) 第 5 节） |
| 用户对某字段犹豫 | 取默认值 + `[假设]`，不追问第 2 次 |

## 5. 用户授权 AI 自主决定时

用户说"你定""你看着办""你专业你来"时，这不是空白支票，必须记录授权边界。

**授权卡（写入确认书「决策记录」栏）**

```text
授权原话："你看着办"
授权范围：视觉方向、版式选择、配色与字体选型
不含：内容事实、涉密信息、时长与页数的硬限制、品牌必用素材
授权时间：2026-11-14
可推翻项：全部 AI 自选方向与参数（用户随时可改）
不可推翻：用户原话给过的字段（见「已确认」栏）
```

**R6 授权不覆盖四类内容**

**触发条件**：用户给出"你定"类授权。
**具体动作**：默认授权范围仅限视觉方向与版式；内容事实、涉密信息、时长页数硬限制、品牌必用素材 4 类仍须逐条确认。判据：确认书中这 4 类字段不得标 `[已确认]` 除非有用户原话。
**常见错误**：拿到"你定"后自行改写用户的数据结论、把 40 页砍到 18 页、把客户名写进标题。这些都不是"视觉方向"。

## 6. 确认书生成规范

**R7 生成时机与展示**

**触发条件**：[conversation-guide.md](./conversation-guide.md) 第 4 节 C1–C5 全部满足。
**具体动作**：按模板生成 `requirement-summary.md`，用 T4 句式展示（"n 条已确认、m 条建议、k 条假设，回'确认'或指出编号"），得到显式回复后才进入阶段 1。用户未回复时不得开始制作，只能继续收集素材。
**常见错误**：生成确认书后自己接一句"那我开始做了"。用户还没读，后面 30 页都建在未确认的假设上。

**R8 篇幅与条数**

**触发条件**：写确认书任意一栏。
**具体动作**：单字段 ≤ 40 字；待确认项 ≤ 5 条且每条附默认值；全文 ≤ 1 页（≤ 60 行）；`[建议]` 条目 ≤ 6 条。超出时按"影响页数 → 影响视觉 → 影响格式"的顺序删低影响项。
**常见错误**：确认书写成 5 页，含 18 条待确认。用户不会读完，只会回"可以"，等于零确认。

**R9 版本与变更**

**触发条件**：确认书已确认后又发生变更。
**具体动作**：变更 1–2 条且不涉及全局参数 → 原地修改 + 变更记录 1 行；变更 ≥ 3 条或涉及色彩/字体/网格/比例 → 升版本号（v1 → v2）并重新展示确认。变更记录格式：`v2 | 2026-11-14 | 时长 15→12 分钟 | 影响：删 3 页过程页`。
**常见错误**：连续改 8 次都不留痕，最后没人知道当前版本哪条作废。

**R10 一页可读**

**触发条件**：生成完毕。
**具体动作**：逐条自检——每个字段有标签、每条 `[已确认]` 有来源、待确认项有默认值、无空字段（空字段写"未提供"，不写空白）、「AI 的初步建议」4 项齐全。
**常见错误**：字段留着冒号不填。后续执行者无法区分"用户说没有"和"忘了问"。

## 7. 已批准清单（唯一能防止「改坏」的机制）

用户在对话里认可的每一项都要落盘，一行一条：

| 版本 | 页码 | 元素 name | 内容摘要 | 认可时间 | 用户原话 |
|---|---|---|---|---|---|
| v1.2 | s07 | img-prototype | 原型机 3/4 视角照 | 2026-11-14 22:10 | 「这张原型机好看，保留」 |

三条使用规则：① 只有用户明确表态才进表，AI 自己觉得好不算；② 进表后默认不可改，确需改动要单独说明并取得同意；③ 每轮修订后核对清单未被动过，被动了按回归缺陷处理（P0）。

配套的动作规则（反馈三问、最小改动、diff 清单）写在 `../workflows/07_revision-and-handoff.md` §7.0。

## 8. 素材授权与工具确认（先许可、再工具、才动手）

**规则：素材动作以「素材授权」区块为准**
- **触发条件**：本轮需要任何外部图片或生成图片。
- **具体动作**：先拿到 Q29/Q30 的显式答复，写入确认书的「素材授权」5 个字段（可否搜集 / 可否生成 / 指定工具 / 禁用来源 / 答复原话与时间）；后续每一次素材动作前回读该区块。字段为空或写「未答复」→ 视为不许，只走几何图形与留白。
- **常见错误**：把"他没说不行"当成"可以"，先搜图再解释；或只在对话里说过一次，换轮次后边界丢失。

## 检查清单

- [ ] 每条记录都带 `[已确认]` / `[建议]` / `[假设]` 标签
- [ ] 每条 `[已确认]` 都能引用用户原话或选择编号（抽查 3 条）
- [ ] 无"用户沉默即确认"的升格记录
- [ ] 待确认项 ≤ 5 条，且每条附默认值
- [ ] 冲突已按阻断 / 可延后两级分类，阻断项均已获用户裁决
- [ ] 授权卡已记录授权范围、时间、可推翻项，且未覆盖四类内容
- [ ] 全文 ≤ 1 页（≤ 60 行），单字段 ≤ 40 字，无空字段
- [ ] 六类回退触发均已排查（推翻、阻断、阈值、全局参数、假设 ≥ 2 条、真实性）
- [ ] 版本号与变更记录存在；变更 ≥ 3 条时已重新展示确认
- [ ] 用户已显式回复"确认"或明确授权，才进入阶段 1
